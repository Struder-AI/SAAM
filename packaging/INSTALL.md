# Install SAAM with a desktop coding agent

Give [this stable installer guide](https://github.com/Struder-AI/SAAM/releases/latest/download/INSTALL.md) to desktop Codex or Claude Code and ask it to install SAAM. Local command access is required.

Read [release metadata](https://api.github.com/repos/Struder-AI/SAAM/releases/latest), with `tags/v<version>` in place of `latest` when the request names a version (`0.3.4`, `v0.3.4` or `/v0.3.4` in a URL); install exactly that version. Require a stable v0.3.2 or newer and select an actually listed `SAAM-<version>-win-x64.zip`, `darwin-arm64.zip` or `darwin-x64.zip` asset. Download it and its `.zip.sha256` sidecar into a temporary folder; verify SHA-256 before extracting the entire ZIP. Stop if no matching release, asset or checksum exists, or verification fails.

Quit an existing SAAM (`saam quit`, or Quit in Studio or the tray menu). Run extracted `app/packaging/windows/install.ps1` with Windows PowerShell `-NoProfile -ExecutionPolicy Bypass -File`, or `app/packaging/macos/install.sh` with bash, as the normal desktop user. Do not run the whole installer as administrator or with sudo. **Installation writes beyond an agent's workspace:** request narrowly scoped execution approval for this verified installer before running it, using the client's supported approval mechanism. A sandbox denial requires that approved execution step; do not retry under the same restriction or silently change the SAAM home. If approval is rejected or unavailable, state the exact reason and present the verified installer command for the user to approve or run. Agent execution approval and operating-system authorization are separate.

The installer uses **C:\SAAM** on Windows or **~/SAAM** on macOS: `app/` is replaceable; `local/` holds `Prints/`, user `extensions/`, `machine-setups/` and `LOCAL-AGENT-NOTES.md`. `state/` persists separately. Existing home data moves into `local/` during exclusive application startup; a failed startup restores its former paths. Conflicting migration entries stop without overwrite. Previous per-user application/data locations, including `.studio-requests`, migrate too; old files stay recoverable in `state/migration/`. It first tries ordinary home creation/access. Only a permission failure requests Windows UAC or macOS native administrator authorization for home preparation. Windows grants the Users group Modify access; macOS normally needs no elevation and restores any prepared home directory to the original user's UID/GID. The authorized helper never installs the application, migrates files or registers clients: those steps, PATH and shortcuts run as the original user. Cancellation, denial or preparation failure stops before application replacement. System directories, filesystem roots and unsafe home links are rejected.

Report the installer's authorization states precisely: requested, helper started, complete, cancelled/denied or failed. Windows may report cancellation and denial together when the OS supplies the same cancellation code. A request alone does not prove a prompt appeared; a started helper alone does not prove installation completed. Native authorization and production ACLs still require fresh-install and upgrade acceptance on Windows and macOS; temporary-root trials do not verify them.

Installation adds `saam` to PATH and registers its skill and command permissions in both clients, including absent clients. Mention SAAM in a new desktop chat; restart an existing client to load the setup. The agent can use `saam call repair_client_setup` for registration problems; unrelated settings survive. Use stdin or `--input FILE` for JSON and retain any returned chat ID. Codex background wakeup remains unverified.

Start from the SAAM icon or the chat's first command. Closing Studio tabs or chats leaves the tray app running; use its Open Studio, Update and Quit menu. A valid optional alpha invite enables official updates and consented diagnostics; later ordinary updates use SAAM's Update action. Verify Studio opens and the client can call `saam call maker_onboarding` before reporting installation complete. Client setup errors do not break the installed app.

To uninstall, run `saam quit`, then `bash ~/SAAM/app/packaging/macos/uninstall.sh --yes` on macOS, or on Windows `C:\SAAM\app\packaging\windows\uninstall.ps1 -Yes` with Windows PowerShell `-NoProfile -ExecutionPolicy Bypass -File`, as the normal user. It removes the app, shortcuts, PATH entries and the client skills and permissions installation added; prints, extensions and settings stay in the SAAM home.
