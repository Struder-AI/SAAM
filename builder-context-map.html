SAAM — Builder Agent Context Map

A builder changes skills, extends Studio and makes isolated, local changes to core — and makes parts to test that work. Builder is the middle of three roles (maker → builder → developer), and builders inherit maker responsibilities. Vertical spine = the required start; a red arrow = an action (run builder-onboarding; later, read CONTRIBUTING before checkpoint/publish); sideways = references reached as the work needs them; blue dashed marks everything one builder-onboarding call returns — all five documents, wherever they sit on this map. It returns no map page unless you pass --area, which is a region path such as core/path or its index; the page comes from the generated map. Grey arrows are reads you choose, not part of any onboarding set. These navigation arrows are distinct from calculated red shared-use references on code maps. Click a box to open the file. Hover to isolate its links.

green dot = also MAKER context (the maker slice a builder inherits). Skill authoring and internals are builder work. Walk the dev map for core/Studio changes or investigation. Skill-script changes need the selected skill guidance and consumed API contracts; they do not automatically need the map. The tan box lower right is the dev map, generated from the source: start at page 0 to keep the whole system in view — even for local work — then follow it to the region, the file and the declaration you are touching. Read a page with node scripts/agent-toolkit.mjs read-map INDEX|DECLARATION and its source with --code; rescan with regenerate [INDEX] and build the human viewer with node scripts/dev-map.mjs build (it is generated and git-ignored). Prefer the walk over text search when orienting. Use read-skill ID --maker --builder, or only --builder if maker context for that skill is already loaded. Reading maps does not change the builder role or authorize broader changes.
