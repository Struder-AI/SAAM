# Development tests

This directory holds only the tests that must be stored. Everything else an
agent needs in order to answer "does this work?" is written on demand by
reasoning from the code and is not committed. Commands and source paths in code
spans are relative to the repository root.

Use [Avoid check spirals](../../BUILDERS.md#avoid-check-spirals) to decide
whether verification is needed. First-use capability is checked by
[setup](../../SETUP.md). The [CI workflow](../../.github/workflows/test.yml)
provides the required `test` status through `npm run setup:check`; the suite
here is run locally and is not an automatic CI gate.

## What earns a stored test

A stored test earns its place only when its oracle cannot be regenerated by
reasoning from the code at the time of need. Four things qualify:

1. **The oracle lives outside the repository** — a physical machine, firmware,
   a controller constraint or an upstream reference. Archive layout, byte
   headers, acceptance envelopes and reference facts cannot be re-derived here.
2. **A safety invariant with no local trigger** — approval invalidation, stale
   view/program rejection, byte-identical delivery, manifest honesty,
   cancellation boundaries, lifetime and shutdown isolation. Nobody editing
   nearby would think to ask, so the test has to.
3. **An expensively discovered defect** — a specific degenerate input, fixture
   or environment condition that reasoning would not rediscover. Keep the
   fixture and its minimal assertion; drop the analytical padding around it.
4. **The MCP adapter surface** — the public agent transport, kept whole.

Anything whose expected value an agent can re-derive from the code (analytical
geometry, path maths, refactor characterization, UI and presentation state,
prose and source-text shape) is written on demand and thrown away. A round trip
between our own writer and our own reader is not independent evidence. No
test-count target or coverage quota substitutes for this judgment.

Run selected files directly, for example:

```sh
node --test core/tests/offset-remnants.test.mjs
node --test skills/vase-wall/tests/vase.test.mjs
node scripts/check-repo.mjs
```

`npm test` runs the stored suite. Stress tests (`npm run test:stress`) and the
repository-document check are separate; focused selection needs no subsequent
full-suite run.
