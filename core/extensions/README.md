# Extension operation ownership

`portable.mjs` coordinates portable interchange through Bundle's explicit
archive/input and part-publication APIs. It owns dependency closure, selected
package provenance, changed-local-copy refusal and library publication. Bundle
claims its destination before validated packages install; if part publication
then fails, installed packages remain and are reported as `installedExtensions`.
Validation never executes entries. This route grants no remote executable
installation authority. `portable-job.mjs` and its worker retain owned temporary
workspace and cancellation/commit handshakes; Runtime provides generic job ports.

`operations.mjs` owns the named blob-field, gridfinity, generic extension, text,
heat-set and library-exchange workflows. It selects techniques and create/update
mode, checks technique restrictions and preserves associated reports. Runtime
routes validated inputs and supplies generic geometry-job lifecycle; it does not
provide hidden technique handlers or machine-settings resolvers.

Bundle's bound `createExtensionBundleAccess` prepares admitted targets and fresh
default/settings snapshots through Bundle's Settings plug. Creates consume that
captured snapshot rather than rereading remembered settings during calculation.
`core/print/extension-edits.mjs` retains revision checks, validation and atomic
publication; `core/print/summary.mjs` owns the existing associated read projection.
Runtime retains selection/request authority, cancellation and work handback.

`contributions.mjs` assembles selected geometry and deposition contributions.
Only geometry, assignments and placement can alter its proposal; an extension
does not supply setup, output, revision or approval authority. `geometry-edits.mjs`
uses the same explicit extension roots for declaration, entry and dependency
selection. `library.mjs` retains local-over-bundled precedence, content/provenance
checks, changed-copy refusal and package validation without entry execution.

These ownership changes preserve existing command schemas, errors and legacy
summary/report fields. They do **not** finish command/query response separation:
identified report retention and explicit command outcomes remain required.
Workspace named operations and the private session registry now live in
`workspaces/agent-operations.mjs`. The workspace server retains normalized design,
preview and transactional replacement-set work through ordinary Bundle commits.
Runtime controls lifetime/browser display and supplies admitted directories.
Workspace reads accept explicit captured legacy `studios`/`viewError` values;
they never invoke presentation or complete queued work. Automatic completed-part
Studio presentation and work-request creation remain a marked legacy Runtime
adapter, with no new authority granted by this extraction. Engine-invoked
extension providers and command response normalization remain unfinished.
No additional root plugs or remote package-admission authority are granted.
