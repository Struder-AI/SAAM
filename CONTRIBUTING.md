# Human contributor rules

These rules are for human contributors. Agents should read this document when a
human developer requests it by name, or when the requested task requires examining
contributor practices, such as a merge audit. It is outside the default agent
reading path.

1. **Start contribution work in a fresh agent session rooted in current SAAM.**
   Use the current main branch of SAAM, or a personal fork based on it, as the
   session's starting project. Have the agent read SAAM's project guidance before
   you introduce another repository, an old conversation or other reference
   material. If an agent session began with an older or different project, start
   a new SAAM session before producing contributions. Referencing SAAM later does
   not satisfy this rule.

2. **Keep agent sessions short and focused.** Give each session a scoped piece of
   work that can finish before the conversation needs compaction. Start a fresh
   session for the next piece.

3. **Treat outside and older work as reference material.** Agree explicitly on
   which components or methods to bring into SAAM. Approval of an idea or
   capability does not automatically approve an existing implementation of it.
   Agents can investigate compatibility and explain the proposed adoption so
   humans can make an informed decision.
