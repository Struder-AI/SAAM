# Skill and extension authoring

Builders compose published interfaces ([orientation](../BUILDERS.md), [boundaries](../MAKERS.md#working-boundaries)); core/shared changes need the developer role. `SKILL.md` owns operations/settings/recovery; optional `BUILDER.md`/`DEVELOPER.md` own author guidance. Keep facts at one owner. [Manual markers](../core/agent/README.md) select machine-specific/on-request sections; unreadable markers remain noted text.
Frontmatter uses `metadata.saam-kind: geometry`, `hybrid` or `guidance`; descriptions guide selection, prefixed “Experimental.” for unvalidated techniques. Keyword skills use keywords alone. [catalog.mjs](catalog.mjs) orders built-ins; refresh `node scripts/skill-digest.mjs` after catalog/description/gate changes.
Verified examples are `examples/NAME.json` containing `{machineId,plan}` (create input without bundleId), linked from the manual and read through `read_guidance`; SAAM never runs them.

Extensions live in `<SAAM home>/local/extensions/ID/`: manifest, manual, scripts, assets. The `saam-extension/1` manifest names a lowercase hyphenated id, dependencies, .mjs entries, license and provenance; [machines](../machines/README.md#adding-a-machine) have their own contract.
Optional `credits:[{name,role}]` and `support:{status,maintainer,scope}` travel with packages. Status is community/supported/unsupported/unspecified; maintainer is a name or null. Workspace UIs provide `[data-saam-workspace-info]` for host display.
Unreadable copies list reasons; missing dependencies/cycles stop use. Factories compose named public engines; private core imports are outside this portable interface. Follow operation [tolerances](../core/README.md#dimensions-and-tolerances) and [adaptive limits](../core/README.md#limits-that-adapt-and-limits-that-are-kept).

Factories/editors share [Geometry construction and query operations](../core/geom/README.md#geometry-query-boundary): synchronous numerical preparation, retained ordinary solids and explicit mesh output. Editors consume resolved values; Recipe retains stable spatial IDs, and solid edits preserve auxiliary curves/points. They also receive named operations and Recipe. `Recipe.operationId(assignments,target)` selects native Slice `{assignment,index,group}` or explicit Trace `{assignment,repetition}` (name/ordinal); assemblies require a part-specific Slice owner. `Recipe.withOperationAfter(assignments,target,after)` returns new assignment records binding hard prerequisites. Predecessors use these selectors, operation IDs, or `{assignment}` for full producer completion; empty producers/selected targets fail. `Recipe.selectEdge(reference)` returns a selected printed edge’s curve, process and readiness reference; use `{assignment,index,edge:{loop,ring?},part?}` for Slice or `{assignment,repetition,edge:{curve},part?}` for Trace. `withOperationAfter` also accepts edge targets, affecting only their courses. `Recipe.slices({assignment,part?})` supplies nominal native layer charts, regions, gaps and process without constructing deposition or execution. These carry no travel policy.
A `process-source` factory receives `{Geometry,Recipe,MaterialRegions,Toolpath,extensionId,settings}`; enabled `plan.skills[extensionId]` settings stay opaque to core. It returns `{declarations,prepare}`. Before geometry preparation, each declaration supplies `{id,assignments}` with unique IDs, explicit parts, Slice/Trace/Inject kinds and authored prerequisites; its primary `id` is among its assignments.
`prepare({plan,placed,componentShells,processForAssignment})` returns `{contributions,failures?,notes?}`. Each contribution preserves its declared assignment IDs/parts/kinds and may supply `geometryCuts`/`solidVolumes:[{part,geometry}]` and `report`. A failure is `{id,message}` for a declared primary. Missing output or a thrown prepare fails that declared work; the shared generation registry removes atomic/hard dependents while retaining independent work. Unreadable declarations reject the request.
`requiredMaterial:[{part,volume}]` uses `Geometry.convexVolume(vertices)` in the prepared model frame, matching the primary part. Owned slice geometry selects the enclosure; Scheduling resolves access in its existing scene. Empty material selection fails. It neither certifies enclosure nor infers an Inject footprint.
Geometry/assignments roll back together; reports appear under `summary.extensions[extensionId]`. Recipe supplies `depositionAssignment`, `injectionAssignment`, `assignmentFilament` and dependency operations. [Plastic weld](plastic-weld/SKILL.md#builder-boundary) is the portable example.

A generated Trace declares `source:{extension,assignment,parameters}`, `curves:[]`, `repeat:null`. Its `trace-source` factory receives `{Geometry,Toolpath}` and returns synchronous `constructLayer({source,parameters})` yielding `{curves,sliceMember?,report}`.
Source context supplies prepared chart/settings, nominal perimeters, fill intent and native stack/index identity. These are construction inputs, not completed deposition. A generated Trace normally uses the chart without native membership; `sliceMember:true` joins that source slice’s completion, so its successor waits for both. It adds no within-slice ordering barrier. Source failures preserve the body; identity/parameters participate in provenance.

Workspaces declare `kind:"workspace"`, `workspace:{ui:"ui"}` and a `workspace-runtime` factory receiving Geometry, Toolpath’s `recipeDefaults`/`curveAssignment`, and `Extensions.text.compileText` (`{geometry,notes}`) with a text dependency.
The factory returns `defaults`, `normalize`, `preview`, `pieces`, `construct`, optional `resources`; `construct(design,pieceId)` returns `{plan,source,requirements,report}`. Preview is explicit. The [host](../workspaces/server.mjs) saves designs/self-contained Bundles; source/requirements are historical provenance, sessions use current recipe dependencies. Extensions own construction/UI; Bundle owns saved parts.

`saam call extension_library` manages selected copies (`list_skills` lists them): checkout makes an override surviving updates; export packages manifests/manuals/scripts/assets/hashes; import validates without execution or replacement of changed copies. Share explicitly; release promotion needs review.
Document resource identity/provenance/license; callers save assets. There is no technical sandbox or automatic I/O permission. Follow [parameter policy](../MAKERS.md#standard-parameter-policy) and [verification guidance](../DEVELOPER-CONTEXT.md#avoid-check-spirals).
