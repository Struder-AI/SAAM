# Skill and extension authoring

Builders build extensions through published interfaces ([orientation](../BUILDERS.md), [boundaries](../MAKERS.md#working-boundaries)); core/shared changes need the developer role. Use whatever development checks get the extension working smoothly, then remove those checks. `SKILL.md` owns operations/settings/recovery; optional `BUILDER.md`/`DEVELOPER.md` own author guidance. Keep facts at one owner. [Manual markers](../core/agent/README.md) select machine-specific/on-request sections; unreadable markers remain noted text.
Frontmatter uses `metadata.saam-kind: geometry`, `hybrid` or `guidance`; descriptions guide selection, prefixed “Experimental.” for unvalidated techniques. Keyword skills use keywords alone. [catalog.mjs](catalog.mjs) orders built-ins; refresh `node scripts/skill-digest.mjs` after catalog/description/gate changes.
Verified examples are `examples/NAME.json` containing `{machineId,plan}` (create input without bundleId), linked from the manual and read through `read_guidance`; SAAM never runs them.

The [canonical Paath extension](../examples/extensions/canonical-paath/SKILL.md)
shows finalized curve/anchor authoring through `Toolpath.paathAssignment`, without
private core imports or conversion back through raw Trace. Local contributors
use the installed contracts, examples and published source navigation; a writable
core checkout is an explicit developer choice. Local extensions with matching IDs
override bundled copies for both desktop and paired web callers.

Extensions live in `<SAAM home>/local/extensions/ID/`: manifest, manual, scripts, assets. The `saam-extension/1` manifest names a lowercase hyphenated id, dependencies, .mjs entries, license and provenance; [machines](../machines/README.md#adding-a-machine) have their own contract.
Optional `credits:[{name,role}]` and `support:{status,maintainer,scope}` travel with packages. Status is community/supported/unsupported/unspecified; maintainer is a name or null. Workspace UIs provide `[data-saam-workspace-info]` for host display.
Unreadable copies list reasons; missing dependencies/cycles stop use. Factories compose named public engines; private core imports are outside this portable interface. Follow operation [tolerances](../core/README.md#dimensions-and-tolerances) and [adaptive limits](../core/README.md#limits-that-adapt-and-limits-that-are-kept).

Factories/editors share [Geometry construction and query operations](../core/geom/README.md#geometry-query-boundary): synchronous numerical preparation, retained ordinary solids and explicit mesh output. Editors consume resolved values; Recipe retains stable spatial IDs, and solid edits preserve auxiliary curves/points. They also receive named operations and Recipe. `Recipe.operationId(assignments,target)` selects native Slice `{assignment,index,group}` or explicit Trace `{assignment,repetition}` (name/ordinal); assemblies require a part-specific Slice owner. `Recipe.withOperationAfter(assignments,target,after)` returns new assignment records binding hard prerequisites. Predecessors use these selectors, operation IDs, or `{assignment}` for full producer completion. Declared empty assignments and native Slice members retain logical completion and transmit their prerequisites without inventing deposition. Absent producers or selected targets fail; an empty member cannot supply a material edge or supporting surface. `Recipe.selectEdge(selection)` returns geometric `curve`, source `selection`, `part`, `process`, advance `materialNormal` and separate manufacturing identity. [Edge selectors](../GEOMETRY.md#selecting-edges) include model mesh chains/named face boundaries, native Slice loops and saved curves, each with optional `range`. Model edges derive every crossed native Slice in `targets`; native Slice boundaries derive one `readiness`, and saved edges supply it explicitly. `Recipe.slices({assignment,part?})` returns owned charts, regions and gaps through the same material preparation as construction, with no deposition/runtime generation. `withOperationAfter` accepts whole-Slice targets `{assignment,index,part?}` as well as operation/symbolic-course targets. Deprecated deposition-edge selectors reject compactly.
A `process-source` factory receives `{Geometry,Recipe,MaterialRegions,Toolpath,extensionId,settings}`; enabled `plan.skills[extensionId]` settings stay opaque to core. It returns `{declarations,prepare}`. Before geometry preparation, each declaration supplies `{id,assignments}` with unique IDs, explicit parts, Slice/Trace/Inject kinds and authored prerequisites; its primary `id` is among its assignments.
`prepare({plan,placed,componentShells,processForAssignment})` returns `{contributions,failures?,notes?}`. Each contribution preserves its declared assignment IDs/parts/kinds and may supply `geometryCuts`/`solidVolumes:[{part,geometry}]` and `report`. A failure is `{id,message}` for a declared primary. Missing output or a thrown prepare fails that declared work; the shared generation registry removes atomic/hard dependents while retaining independent work. Unreadable declarations reject the request.
`requiredMaterial:[{part,volume}]` uses `Geometry.convexVolume(vertices)` in the prepared model frame, matching the primary part. Owned slice geometry selects the enclosure; Scheduling resolves access in its existing scene. Empty material selection fails. It neither certifies enclosure nor infers an Inject footprint.
Geometry/assignments roll back together; reports appear under `summary.extensions[extensionId]`. Recipe supplies `depositionAssignment`, `injectionAssignment`, `assignmentFilament` and dependency operations. [Plastic weld](plastic-weld/SKILL.md#builder-boundary) is the portable example.

A generated Trace declares `source:{extension,assignment,parameters}`, `curves:[]`, `repeat:null`. Its `trace-source` factory receives `{Geometry,Toolpath}` and returns synchronous `constructLayer({source,parameters})` yielding `{curves,sliceMember?,report}`.
Source context supplies prepared chart/settings, nominal perimeters, fill intent and native stack/index identity. These are construction inputs, not completed deposition. A generated Trace normally uses the chart without native membership; `sliceMember:true` joins that source slice’s completion, so its successor waits for both. It adds no within-slice ordering barrier. Source failures preserve the body; identity/parameters participate in provenance.

A `part-geometry` factory returns `{edit,build}`. `edit({base,parameters,request},services)` returns the next `{parameters}` (its own JSON, saved as given) or `{remove:true}`; `build({base,parameters},services)` returns `{solid,materialParts?,label?,rows?,notes?}`. Part edits keeps the result as a part geometry record on the selected part and passes nothing else of the recipe. When a record beneath it changes, each record above is rebuilt from its own parameters, so an extension never reads another's saved form. `services` holds Geometry and `Extensions[id].build` for each declared dependency with a part-geometry entry. [Text](text/scripts/part-geometry.mjs) is the example.

An `operation-edit` function receives `(request,{Geometry,Recipe,Toolpath,part})`, never the recipe, and returns `{add?:[assignment],change?:[{id,set}],remove?:[id],report?}`: the operations it adds, appended after the existing assignments under IDs not already in use, the fields it sets on existing assignments it names and the assignments it removes. `Recipe.assignment(id)` reads one named assignment and `Recipe.preparedPart(part)` the part's prepared shell; Recipe’s selectors and edge construction read the part on SAAM’s side. [Bridging](bridging/scripts/edges.mjs), [hole transitions](hole-transitions/scripts/edit.mjs) and [line text](line-text/scripts/edit.mjs) are examples.

Workspaces declare `kind:"workspace"`, `workspace:{ui:"ui"}` and a `workspace-runtime` factory receiving Geometry, Toolpath’s `recipeDefaults`/`curveAssignment`, and `Extensions[id].build` for each declared part-geometry dependency (for example `Extensions.text.build({base:null,parameters:{features,standalone:true,toleranceMm,maxEdgeMm}})`).
The factory returns `defaults`, `normalize`, `preview`, `pieces`, `construct`, optional `resources`; `construct(design,pieceId)` returns `{plan,source,requirements,report}`. Preview is explicit. The [host](../workspaces/server.mjs) saves designs/self-contained Bundles; source/requirements are historical provenance, sessions use current recipe dependencies. Extensions own construction/UI; Bundle owns saved parts.

`saam call extension_library` manages selected copies (`list_skills` lists them): checkout makes an override surviving updates; export packages manifests/manuals/scripts/assets/hashes; import validates without execution or replacement of changed copies. Share explicitly; release promotion needs review.
Document resource identity/provenance/license; callers save assets. There is no technical sandbox or automatic I/O permission. Follow [parameter policy](../MAKERS.md#standard-parameter-policy) and exercise the extension through its [builder use context](../BUILDERS.md#testing-through-the-use-context).
