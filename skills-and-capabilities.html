Caveats: where "capabilities skills can call" doesn't quite fit

  1. There is no declared skill API. Skills import core modules by relative path (../../../core/…). This list is what they actually import, so it's the de facto surface. Only parts of it have written contracts: shared offsets and intersections (core/region/README.md, which skills are required to use), skill-result composition (core/path/README.md) and geometry for skill authors (core/geom/README.md).
  2. Calls go both ways. Core calls printing skills too: core/print/generate.mjs statically imports each producer (fullFillResult, vaseWallResult, waveResults …) and dispatches it. Producers return {id, operations, report} to the composer. core/print/bundle.mjs also imports pipe-cladding directly.
  3. Some skills are mostly core. mesh-tools and advanced-vase-wall have no scripts of their own. Repair lives in core/print/repair-stl.mjs plus native CGAL, and advanced vase is part of vase-wall. text and heat-set-inserts put their main work in core/print/text.mjs and heat-set.mjs. rimming-normal reuses rimming-planar's producer.
  4. Two import paths for the same booleans. core/region/boolean.mjs re-exports union / intersect / difference from intersection.mjs, and skills use both paths.
  5. Not included: imports from skill tests only, such as core/tests/fixtures/* and core/export/registry|griffin|bambu. gridfinity's catalog description is literally "gridfinity" (its manual says this is intentional), so its description here is taken from the manual body.
