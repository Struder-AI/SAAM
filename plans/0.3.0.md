# SAAM 0.3.0 intent

Owner release intent, 2026-10-01: **give our installation URL to desktop Claude Code or Codex → the agent installs SAAM with an app icon → first launch prompts for an invite to connect to the update service → subsequent updates work by clicking the in-app update button.** Deploy when this complete experience works. [0.3.1](0.3.1.md) architecture work continues independently and must not block it; historical release assignments are superseded.

- Testers install during chat by giving desktop Codex or desktop Claude Code a URL. Remove web-chat operation and its connection/session machinery; retain the local Studio–agent request/event channel and existing priority delivery. Alerts carry queued lower-priority observations; tool-result/explicit-read drains remain a review detail, separate from service diagnostics.
- SAAM works without activation. An invite entered in Studio enables official alpha updates and live diagnostics only. Unactivated use collects no diagnostics; missing/invalid codes or service failure never disable making, viewing or exporting. Replace the former chat relay with an update/diagnostics service, provisionally **Release & diagnostics service**. No offline grace/revocation subsystem.
- Keep user storage outside the replaceable installation, preserving bundles and local edits. A repository checkout is a separate developer workflow. Do not require 0.3.1's extension migration, neutral-engine refactor, architecture audit, instance-ownership work or tour redesign to finish before the installation trial.
