# Proposed target contracts and one complete flow

2026-10-20. A design proposal for review, not a claim that SAAM has been migrated.
[Owner intent](0.4.0.md) governs. The viewer
reads the canonical definitions in [contracts/map.json](../contracts/map.json).
The approved overall SAAM responsibility remains word for word there.

## Nesting and responsibility

Choose map density for useful contracts, not node count. Scheduler stays a
separate root responsibility. Geometry, Regions, Construction, Settings, Bundle,
Studio, Export, CLI, Context, Extensions and Runtime also expose distinct
obligations worth reviewing directly. Context and Extensions are separate:
Context supplies guidance and discovery; Extensions execute named techniques.
The map system does not need to map itself, so there is no Contracts node.
Narrower request handling, revision storage, Slice/Trace/Inject construction,
workspaces, viewers and writers live below those contracts. Current directory
boundaries are migration evidence, not the design.

CLI is the primary agent entry. A separately provided private MCP connector,
outside the public SAAM implementation, adapts the same named operations. The entry
module parses, validates and routes calls; it owns no technique or fabrication
workflow. Extensions compose only their declared shared interfaces. Runtime owns
job lifetime, observations and host integration separately, so neither entry
transport nor extension code needs a second job system. Its root placement is a
proposal to expose that distinct technical obligation, not an owner-approved
new domain contract.

Open-source SAAM remains independently usable through CLI and Studio. The private
provider project owns relay hosting and MCP/OAuth adaptation. Public command
semantics, caller authority, job identity and returned values are the integration
contract. The public map shows the Agent plug and CLI, not the private connector's
internals. A generic local bridge may consume that interface; choosing its
packaging/protocol and extracting existing source remain migration work.

Bundle owns consistency across requested part operations and their publication;
the engines own the algorithms. This keeps orchestration out of client adapters
without creating a second numerical implementation or a compulsory stage gate.
Each operation validates only its own prerequisites. The example below does not
force standalone Trace/Inject or intermediate edits through a complete recipe.

## Canonical wires and refinement

A wire is declared between direct children of its owning map. That declaration
grants the external permission. Submaps assign the same canonical wire to local
children through `refinements`; they do not independently author another plug
contract. Multiple internal users can implement the same interface family.
Runtime values distinguish flow, invocation and consumer identities.

Adding a child-to-external wire under the child's scope is rejected. A new
parent permission must be an explicit wire declaration at the parent scope.
An unassigned parent plug remains visible with its canonical identity; no child
implicitly acquires it. Internal child wires never manufacture parent permissions.

Command and query are the two semantic link kinds. Both name request and reply
types; values are their payloads. Cancellation and progress recording are commands,
and status reads are queries. Follow the shared wire-direction rule.
Aggregation and terminal placement do not change causal direction or the wire contract;
requests and replies remain on the same canonical wire.

## Example flow

The viewer's **Example flow** walks through symbolic identities, not a live run:

1. An agent uses Context to select an extension and read its manual, then calls
   `saam call apply_extension --input request.json`. The request names an existing
   bundle, expected edit revision, extension and technique inputs. A new part can
   first use `create_bundle`.
2. CLI routes to Extensions. The selected extension reads part E0 through Bundle,
   uses the shared Geometry interface to prepare G0, and returns its geometry and
   recipe proposal. Bundle validates and commits both atomically against E0.
   These are separate visible plugs; CLI implements none of this domain work.
3. `saam call generate_toolpath --bundle-id PART` reaches Runtime Jobs, which
   captures the required saved identities and supplies the explicit Construction
   command inputs. Bundle owns saved values and guarded publication.
4. Geometry produces G1; Regions allocates R1 for this Slice example.
5. Construction **3.0** admits the command; **3.1/3.2/3.3** produce work and
   **3.4** applies requested finishing. **3.6** supplies immutable W1 to Runtime
   and commands **13** to schedule that exact work with the supplied constraints.
   Runtime makes no separate scheduling call. Numerical extension queries remain
   pure and do not start this handoff.
6. Scheduler resolves manufacturing dependencies and each logical tool's supplied
   or default nozzle type, then supplies S1 directly to Runtime, preserving W1's
   geometry and anchors through any exact splits,
   with an index per output entity and captured nozzle assumptions. Machine
   assignment later maps logical indexes to concrete toolheads; uncovered
   assumptions require Scheduler qualification through Bundle before publishing
   the review capture. Export realizes physical transfers for that captured order.
7. Runtime submits the supplied G1/W1/S1 values to Bundle, which publishes their
   coherent identities against the captured revision.
   Failed, cancelled or superseded production retains prior published results.
8. Runtime observations expose the actual intermediate values by flow, stage,
   wire instance, type and consumer. Inspection cannot influence command choices.
9. `request_review` selects existing values. Studio can show Paath before or after
   scheduling; only execution playback requires an order. Normal and development
   channels reuse the same typed viewers and complete-data access.
10. The person's Export action produces approval A1 for the displayed identities.
   Bundle freezes capture C1, including resolved settings and writer identity.
11. Export translates C1 to files and an export receipt. Later editable-part
    changes cannot retarget C1. Deliver files; do not operate hardware.

Approval, capture and receipt are different lifecycle values. Paath can be a curve
or a stationary point; work is its manufactured collection. A schedule adds order
and may split entities while preserving geometry and anchors. The [Paath
proposal](0.4.0-paath.md) records completed degree/interpolation research and the
remaining representation decisions.

## Migration and command continuity

The viewer's CLI submaps expose 67 call operations and 14 accepted top-level verbs
from the authored operation catalog, including
complete schemas/options, effects, outcomes and owner/source bindings. The shared
agent reader exposes the same contracts. Dynamic extension commands and native
Studio Export remain additional surfaces. Registration/schema/binding comparison
passes; unresolved ownership and routing obligations remain explicit. Visibility
and schema parity are not behavioral conformance.
Default policy: preserve the output deliverables and equivalent commands/options.
Preserved capabilities and deliberately separated effects are verified per owner,
not inferred from the catalog.

Specific review proposals:

- Make `get_studio_events` an observational cursor read. Move acknowledgement to
  an explicit command, retaining equivalent event delivery.
- Generalize cancellation around stable job identity, retaining
  `cancel_studio_calculation` and its current arguments as an adapter while needed.
  Keep ownership and stale-target protection.
- Retire the strict legacy `adjust_recipe.expectedRevision` alias through trivial
  mapping to `expectedEditRevision`; reject conflicting values. Keep
  `expectedStudio`/selection guards because they protect a different authority.

Keep `generate_toolpath`, Slice/Trace/Inject authoring, partial recipe creation,
complete-geometry discovery, units, placement, process controls and meaningful
tolerances. Remove a sampling option only after proving that the replacement
preserves authored meaning and numerical behavior. A new representation alone
does not justify removing an input capability.

Source bindings in the viewer are partial migration evidence. Engine rewriting,
MCP restoration, live value capture, compatibility verification and conformance
enforcement remain implementation work after contract review.

## Migration readiness — 2026-10-20

The earlier Paath gate was resolved by the subsequent owner decisions and explicit
instruction to complete the migration. Work is active. Contracts lead code;
internal refinements stay within their parent promises and changes propagating
to map 0 require owner review. The [implementation ledger](0.4.0-migration.md),
[session audit](0.4.0-session-intent-audit.md) and [baseline audit](0.4.0-baseline-audit.md)
retain incomplete obligations and observed regressions. An old pause/prototype
label grants no permission to disregard the contracts.

After the owner accepted neutral tool indexes, per-index scheduling nozzle types
with defaults and later machine toolhead assignment, the first migration slice
implemented the shared source reader and developer onboarding. Both agents and
the viewer now consume `core/contracts/reader.mjs`; the sole implementation moved
out of the viewer. Developer onboarding returns map 0 and targeted reads use
`node scripts/agent-toolkit.mjs read-contract ADDRESS`. Automatic delivery of the
whole implementation account is replaced by focused contract navigation, while
area manuals, local notes and extension discovery remain. This does not migrate
the numerical pipeline or decide packaging/executable-extension admission.

The next bounded runtime slice is Context/manual discovery ownership. Before
moving a handler, carry its complete request, authority, outcome and delivery
semantics into the owning contract. The continuity assessment found these beyond
the 61-name inventory:

- Studio selection guards, request claim/handback, revision and cancellation
  identities, pending observations and failure-time work requests.
- Dynamic checkout registrations, installed extension-specific request schemas
  and engine-invoked provider contracts.
- Native Studio Export's click-time capture plus bytes-versus-download-link
  delivery; an agent operation cannot replace human approval.
- Read-labelled operations that drain events, claim requests or write artifacts.
  Preserve the capability through explicit command/query ownership, rather than
  deleting the effect or trusting the existing `readOnly` flag.
- Complete editable geometry, partial construction, portable bundle exchange,
  STL repair artifacts/units/provenance and workspace ownership.

No command or option is removed in this slice. The existing strict revision alias
is still the only trivial-mapping candidate already proposed. No sampling,
tolerance, geometry, process, units or placement control has been shown disposable.
Schema/output continuity must be established incrementally for each moved group;
source inspection is not end-to-end verification of all operations.

Review these seams before migrating their behavior:

- **Extensions:** agent-invoked techniques, engine-invoked process/Trace sources,
  machine adapters/profiles and workspaces are existing roles. The current map
  illustrates the first role well; provider invocation and ownership need explicit
  contracts. See `core/extensions/process-sources.mjs`,
  `core/print/trace-source-preparation.mjs` and `core/export/registry.mjs`.
  A plugin may implement a core-owned interface; distribution as an extension
  does not alone determine the algorithm's contract owner.
- **Scheduler / Export / approval:** Bundle qualifies the saved schedule for
  selected nozzles through its existing Scheduler plug before publishing review.
  Export checks the captured assumptions and resolves physical transfers; it
  cannot call Scheduler or reorder deposition. Missing mappings/failed
  qualification preserve inspectable work and a finding, with Export unavailable.
  The reviewed schedule/settings survive later edits. No Export-to-Scheduler
  permission is added.
- **Paath / work / schedule:** [the Paath decision proposal](0.4.0-paath.md)
  records current producer/cost research and recommends degrees 1–3 plus canonical
  rate/aspect anchors. Owner direction removes intrinsic tool roll; adapters derive
  it. The authored type now defines independent material-section orientation,
  requested-time point anchors, dose/hold phases and separately indexed split
  entities. Canonical publication uses local rate/aspect and tool axis. Historical
  cumulative-volume/full-frame inputs retain a reader; their local section law
  is not replaced by renaming endpoint keys. Broader producer/consumer integration
  remains subject to the migration ledger and actual conformance evidence.
- **Bundle / partial results:** current generation retains independent successful
  work while removing failed work and hard dependents. Distinguish a completed,
  explicitly partial result from an operation failure. Atomic publication must
  not erase this capability or silently present incomplete work as complete.
- **Runtime / connector / package admission:** settle the local bridge's public
  adapter versus private add-on packaging, pairing/session identity and optional
  desktop versus required web connection. Installed extension authoring remains.
  A web-authored package can be imported locally; its admission and execution
  authority are distinct from ordinary part commands. Current import validates
  all bytes without executing scripts, but loading an entry executes local Node
  code. Human-initiated import is a proposal for the new web flow.
- **Studio / complete views:** use the same identified values in normal and debug
  views. Region/UV-stack inspection, unordered Paath, parameter-linked profiles,
  stationary work and failure witnesses need explicit viewer coverage. A web
  browser on a different device also needs a review/artifact delivery route.

The inspected capabilities fit the root responsibility structure, but some
required plugs and data semantics are still missing. Contract validity is not a
whole-capability coverage proof. These gaps are review questions on the owning
viewer cards; no permission was added merely to match existing imports.

This readiness assessment predates implementation. The owner subsequently
approved the [guidance replacement](0.4.0-guidance.md): explicit state ownership
and declared callable contracts replace the two blanket syntax restrictions;
routine influence solving is no longer a development prerequisite. Other
permissions remain unchanged. The shared reader/onboarding, current Paath,
operation ownership, immutable report queries, faithful retained peeks and
private-provider extraction are now implemented for the scopes recorded in
[DEVLOG](../DEVLOG.md). Portable exchange, provider interfaces and remaining
integration are tracked as unfinished rather than inferred from these milestones.
