# SAAM 0.3.6 intent

Owner, 2026-10-05: mesh import repair and blob field ship in 0.3.6, after the 0.3.4/0.3.5 Update verification releases.

| Item | Evidence, direction and acceptance | Status |
|---|---|---|
| Mesh repair redesign | Windows 0.3.2 brain imports and a moon import fail CGAL self-intersection repair; likely brain sources reproduce the rejection, while the exact tester inputs remain unidentified. Relaxing genus preservation also fails. Consider general solid-boundary reconstruction using exact triangle-intersection arrangements and oriented winding classification, with libigl/CGAL as a candidate. Further consideration must settle semantics, backend and feasibility before implementation approval. Any selected approach must preserve intended cavities and unaffected geometry, report changes, retain original bytes/cancellation and pass closed-manifold/contact checks, exact decimal STL reimport and prior successful imports. [Investigation](../DEVLOG.md#2026-10-02--record-mesh-import-investigation-and-owner-decisions) owns evidence and coverage limits. | Owner, 2026-10-05: 6-7 (mesh import, blob field) is 0.3.6. Blob field implemented and verified by a worker (branch worktree-agent-a16fc574477184b80, b1539395: Geometry-owned marching tetrahedra; merge reverted from 0.3.4 in d69c38c2); bundle save pause from canonical hashing remains (proposed: one fast canonical serializer replacing 8 copies, byte-identical first). Mesh import implemented by a worker (branch worktree-agent-a5816a589592514e4, 2d97ce18: native `cgal-solid-repair/2` solid-boundary reconstruction from CGAL 6.2.1 autorefinement and exact winding; exact cleanup cancels opposed coincident faces): Thingi10K 44374/44375 reconstruct closed and exactly non-intersecting in about 8 s but fail the 1e-9 mm contact rule (188/93 pairs, cavity floors about 1e-5 mm from the cut bottom). Owner decision pending: exact contact contract, regularisation, or keep the contract. Mac helper needs a Mac build |
| Use SAAM, else an extension | Owner, 2026-10-05, after a tester's agent built a vase-mode program in a custom script (formula-driven shape; a bug killed a print; too-fine tolerance; an over-conservative RAM check): "If saam can do it, use saam. If it can't, build an extension that can." Most things should be doable with extensions; building outside extensions is a SAAM bug the agent reports. Maker and builder guidance state this route; a `saam` command files the bug report to the relay (as Studio's Report a bug). | Implemented: `MAKERS.md#working-boundaries`, `saam call report_bug` |
| Approved 0.3.4/0.3.5 rows | Owner, 2026-10-05: every approved, unimplemented row from [0.3.4](0.3.4.md) and [0.3.5](0.3.5.md) ships in 0.3.6 (tray open without a fixed timeout, dimming by client turn-end signal, couplings C1 and C2, approved dev-map follow-ups). Owner-pending rows stay there. | Tray and dimming in progress; rest queued |
| Dimensions and tolerances | Owner, 2026-10-05, on mesh contact pairs failing a 1e-9 mm rule: "I don't know why the hell we are doing anything at 1e-9 mm"; crucial intent for 0.3.6. Everything in SAAM, and anyone building extensions, works from the dimensions SAAM actually deals with (build volumes of hundreds of mm, nozzles and lines of tenths of a mm, layers of hundredths, machine and program resolution near 1e-3 mm) and uses tolerances derived from them, each naming what it protects. Audit and replace arbitrary tolerances; guidance for developers and builders keeps tolerance awareness in the culture and checks keep it from drifting. Mesh repair follows: features far below print resolution produced by repair are closed and reported, not rejected. | Approved; not started |
| Advanced vase tiles keep their size | Owner, 2026-10-05: an advanced vase mode where the tile does not stretch with the vase's diameter: a wider part of the vase (higher up, say) has more courses per layer than a narrower part. Today pattern X is in perimeter turns, so a fixed course count per turn stretches with the perimeter. | Approved; not started |
| Dimming means the agent is at the SAAM desk | Owner, 2026-10-05, refining 0.3.5's turn-end row: dimmed means the agent is working at the SAAM desk, not interacting with the person; un-dimmed means it is at the counter, messaging in chat (or has been, and nothing changed since). Two moves from desk to counter: the agent finishes something, or the person interjects in chat mid-turn; later SAAM work moves it back. Both on Claude Code and Codex where the client allows; design (per provider) goes to the owner before final approval. | Designing |
| Machine adapters for builders | Owner, 2026-10-05: a friendly way for builder agents to build export adapters for new machines, as extensions have: guidance, sensible standards (the owner reviews the standards list before adoption) and, most importantly, a standard set of plugs a new machine adapter plugs into. Today each machine has an exporter and a player that decodes its program for Studio (`core/export/*.mjs`, `*-player.mjs`). Owner decision, 2026-10-05: the viewer shows the SAAMpath, not a decoded program. Adapters are responsible for translating SAAMpath accurately into their machine format; a new adapter's verification checks are debug-only and are removed once it is known to work. SAAMpath and machine settings are the only transfer medium into an adapter: any other link from Toolpath or Geometry to an adapter must be shown to the owner with its case and specifically approved, otherwise it is not allowed (existing links included). | Designing; standards list and existing links to the owner |
