# 0.3.1 tour policy proposal

Requested by Nave on 2026-10-01; **for review, not approved behavior**. The current [tour policy](../examples/prints/README.md#maker-agent-participation) remains in force. This proposal keeps the tour inside ordinary Studio and uses the website as its outside reference.

| Topic | Proposed policy |
| --- | --- |
| Purpose | Teach the smallest complete cycle: change a shape, inspect it, change how it prints, review the checked output and export. Tutorials cover additional techniques separately. |
| Sequence | Start with one editable part; geometry edit → toolpath playback → one process edit → actual printer/material review → exact-program confirmation/export. Make the second shape, library navigation and STL import optional side lessons rather than mandatory gates. |
| Agent and Studio | Studio gives the current task. The agent responds to requested edits and gives one concise process suggestion when that lesson calls for it. No duplicate narration, ceremonial introductions or automatic congratulations speech. Completion says the file was downloaded and offers further help once. |
| User control | Back, exit and explicit resume remain available. A fresh-tour request creates fresh copies; resume uses saved progress. Honor a different task by offering to exit; never silently edit another part or advance the lesson. |
| Printer selection | Use a clearly labeled example setup for initial playback. Before export, establish the user's actual machine/material and regenerate only what those changes require. No implication that the example file is ready for their printer. A user without a printer may finish a viewing-only tour without exporting. |
| Progress | Gate only on the relevant result becoming visible, not arbitrary delays or mandatory chat wording. Process-edit completion requires the new path on screen. Playback remains freely scrub-able. Failures preserve the lesson and report a concrete next action. |
| Confirmation | One confirmation covers current settings and the exact displayed checked program. Pending edits disable Export; completion follows receipt of those bytes. No added approval record, second ceremony or regeneration at download. |
| Presentation | Plain task labels, short instructions and restrained highlights. Keep model interaction available. Avoid blinking decoration and repeated explanatory copy; honor reduced-motion preferences. |
| Acceptance | Exercise fresh start, requested edits, back/resume/exit, a failed generation, missing extension, viewing-only completion and exact export in ordinary Studio. Keep physical print qualification separate. |

Owner decisions: approve the shorter core sequence with optional side lessons; allow viewing-only completion; replace prescribed chat ceremonies and blinking highlights with the restrained behavior above. These are changes from the current policy and must be settled before implementation.
