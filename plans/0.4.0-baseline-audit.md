## Confirmed high-impact findings

### B1 — P1: finalized varying sections change material and dimensions

**Confirmed numerical regression; open.** Unchanged `depositCurves` produced a fixed-width 0.4 mm stroke with points `[0,0,0.2]`, `[1,0,0.2]`, `[10,0,0.2]`, segment heights `[0.2,0.8]`, upright normals and speed 20 mm/s. Finalized segment volumes total 2.9600000000000004 mm³. Publishing the identical minimal finalized construction through baseline/current `constructionPath`, then querying `prepareCurvePath`/`curveRange` with length and volume tolerances 0.00001, gave baseline `/2` volume `[2.96,2.96]` versus current `/3` `[2.48,2.48]`: 16.2% material loss. Both reported `compaction.volumeErrorMm3=0`. Current `curveAt(...,0.3)` reconstructed width 0.5 mm instead of finalized 0.4 mm; section-error summary was approximately 0.5629 mm.

The probe loaded baseline modules from `git show b0d6dd27` through data URLs, rewriting relative imports to workspace numerical dependencies. It did not run fabrication. Evidence: `core/path/construction-profiles.mjs:57` connects finalized segment values at centres; `constructionScalarProfiles`/`canonicalAuthored` use this fallback without a surviving canonical witness. `construction-path.mjs` replaced cumulative volume while retaining zero reported volume error. A subsequent zero-rate-knot safeguard does not change this positive-rate example.

Trigger: supported generated/contact-adapted per-segment sections without canonical witnesses. Owner: Paath publication/reader; `part-construction` → `part-scheduling`. This is actual material/section drift, not optional reporting totals. Fix: bounded lowering preserving finalized physical law and truthful error bounds. Intentional loss needs an explicit owner decision; replacing representation does not waive physical meaning.

### B3 — P1: continuous axes acquire an almost 180° machine roll

**Confirmed numerical discontinuity plus actual writer consumption; open.** Axes `[sqrt(1-y*y),y,0]`, `y=0.99899` and `0.99901`, differ by approximately 0.02563018°. Current derived tool-up vectors differ by 179.97436982°.

Evidence: `core/path/pose.mjs:18` calls `axisFrame`; `core/geom/frame.mjs:79` switches reference-up at `abs(dot(axis,up))>0.999`. Current canonical `curveAt` imposes this pose on every query. Unchanged `machines/denso/denso.mjs:56–58` consumes tool-up as emitted physical orientation; kinematics rotates it rather than choosing continuous roll. Baseline reader interpolated supplied pose rather than imposing this switch. The helper predates migration; its newly universal use and machine consumption create this risk.

Authored full roll was explicitly retired. That does not authorize artificial physical roll flips. Owner: Paath numerical basis versus machine adapter qualification. Keep the computational basis from becoming authoritative robot roll; adapter must choose continuous feasible roll. No robot program or physical motion was executed; collision severity is not experimentally established.
