owner's direction. Recommendations here are not approved hard rules or evidence
that the new architecture is implemented. Current implementation remains described

The working viewer prototype now provides the
requested map: nodes and links open their contract details when clicked. Its
curated coverage is partial; it does not implement live peeks or conformance.

## Recommendation

Ship authored, versioned contract maps and a small shared query/view model with
source. Reuse the old design viewer's navigation, placement and wiring. Run code
analysis as separately scoped conformance evidence. Reading contracts, editing
code and opening the viewer should require no influence solve. First prove one
useful vertical slice: Scheduler contract, Paath type, before/after peeks and
source bindings. Then expand map 0 and reconcile implementations by contract.

Keep the relay topology, but restore MCP against today's Application operations;
the historical adapter/runtime must not become a second execution lifecycle.
Settle Paath and guidance before a broad engine rewrite.

## One contract model, several views

Owner clarification, 2026-10-20: keep command/query separation. A plug is an
end of a wire, not an independently authored contract; peeking at either plug
identifies the same wire value.

A node states its responsibility and boundary. Owned state, preservation promises
and meaningful failure behavior belong in that prose when needed. Its connected
wires are derived from the wire records. Source references support navigation and
evidence; they do not add implementation details to the normative contract.

A wire names its two endpoints, data type and any additional promise specific to
that interaction. Both plugs expose that same contract. Type definitions own
shared version, units and numerical semantics. State stream ordering or snapshot
lifetime only where those distinctions matter; do not require an inventory of
fields on every wire. Command/query separation stays an operation obligation.
Callbacks, workers, shared objects, filesystem reads and initialization can all
carry influence; the boundary still has to account for those interactions.

The prototype keeps metadata such as stable identity, layout, source references
and open review questions alongside contracts so the viewer can navigate them;
these are not additional contract obligations.
The authored graph is the permitted architecture. Source evidence overlays
observed relationships. A missing authored wire means no permission at that
scope; a missing observed wire means nothing unless that analysis proves coverage.
A child map refines its parent's plugs and invariants. It cannot add an external
interaction or weaken an enclosing obligation. Agents can author internal
contracts; changed parent permissions must be explicit in the review diff.

Keep contract approval separate from conformance: draft/accepted contract status,
then per-claim evidence such as checked at a revision, violation, or not checked.
A changed source file can invalidate a check without invalidating the contract.
A missing type or dangling plug is a contract-definition error. Viewer cache
currency is a third, presentation concern; serve current authored data directly.

Suggested query addresses preserve the old progression: `0`, node ID/map,
`@link/MAP/FROM/TO`, `@type/paath`, `@path/FILE`, and an implementation-evidence
address. Numeric page aliases remain convenient; stable IDs own links and layouts.
CLI, MCP and the human viewer consume the same projection of one model. Agent
reads include responsibilities, boundary plugs, types and obligations visible to
the human, with explicit links to full detail. Do not independently summarize
away exclusions or silently cap a large map.

Proposed source layout: `contracts/` owns accepted definitions/types/maps and
layouts; a small reader validates/resolves them and produces both views. Component
manuals retain usage and detailed algorithms, linked by contract ID rather than
copying invariant prose. `ARCHITECTURE.md` becomes an overview/runtime/deployment
index into contracts. Keep scanner stores, solves and local source caches outside
the shipped definitions. Source shipping is required; whether installed maker
packages include the full development viewer is a separate packaging choice.

## Scheduler as the first concrete contract

| Item | Proposed content |
|---|---|
| Responsibility | Order admitted manufactured Paath under supplied hard prerequisites, physical constraints and allowed traversal changes; create neutral travel intent. |
| Input | Immutable Paath work set, its identity, manufacturing prerequisites, declared start and neutral policies. These may be one typed request; the contract must expose all of them. |
| Output | Ordered references/ranges into the same work set, travel Paath and scoped findings; no deposition edits. Exact coverage once, preserved volume/pose and hard prerequisites. |
| Approved dependencies | Explicit numerical-query interface for conservative geometry/curve queries; progress/cancellation control when supported. Required dependencies are visible plugs, even if injected as capabilities. |
| State and effects | Private evictable caches only; no Bundle I/O, selected-machine lookup, recipe reread, global state or undeclared callbacks. Caller supplies values and owns saving. |
| Refinement | Whole work first. Cuts/interleaving only for actual constraints; numerical subdivision alone does not change execution. |
| Failure | Infeasible prerequisites, access or numerical uncertainty gives a scoped failure, retaining the source; no unchecked successful schedule. |
| Inspection | Select input/output by the same flow and source identity; distinguish source ranges, execution order, transfer intent and physically resolved travel. |

This is more specific than “Paath in, ordered Paath out” because existing behavior
needs prerequisites and numerical access. The simple root label remains valid;
submaps expose these details. Every additional plug needs a reason, not automatic
permission derived from today's imports. In particular, the current Recipe →
Scheduling relationship should be reviewed for an explicit captured-input wire.

## Enforcement without an analysis lifecycle

Use cheap structural checks for contract references, compatible plugs, child
refinement and source imports across owned modules. Bind public operations to
contracts; count unresolved dynamic calls and unassigned code as unknowns. Folder
ownership can seed bindings, but is not proof of all effects. Package/module
isolation and supplied immutable values remove many illegal capabilities by
construction. Check admission once per unchanged value, rather than adding repeated
whole-path validation to every read.

Retain generated leaves, link analysis and runtime observations for investigations
and a separately invoked enforcement role. Reuse valid results and analyze changed
interfaces/affected closures. A trace proves what ran, not absence of other paths.
An agentic reviewer compares the diff against node obligations, public plugs,
callers, state access and representative flows. Each finding links the contract,
source and affected case. “No findings” is review evidence with a named scope,
never a proof of whole-program causal completeness.

A contract-layer review should show changed roles/plugs/types/invariants, affected
consumers, known violations and evidence scope, with source available underneath.
A code-only change can still violate an unchanged contract, so conformance review
must not depend solely on a contract diff. Do not auto-add a wire or relax a
contract merely to make the implementation conform. Unknown analysis remains
visible in the evidence view; opening or editing contracts never runs a solve.

## Paath: small primitive, explicit work and order

Treat SAAMpath/Paath/path as equivalent domain words. Use stable schema IDs in
code to distinguish a curve, a collection of manufactured work and its ordered
execution. Those containers are necessary structure, not rival path authorities.
An unordered source has no global playback order; inspect individual curves or
an explicitly labeled source listing. Scheduling supplies execution order.

The next degree bound remains open pending investigation (owner, 2026-10-20). Current Geometry admits degrees 1–3. Degree-1 NURBS can represent
polylines exactly, with the original parameter positions retained; measure byte
cost before deciding whether a compact polyline encoding remains an equivalent
storage form. Do not refit valid source geometry merely to standardize spelling.

| Information | Recommendation / unresolved semantics |
|---|---|
| Position | Limited-degree positive-weight NURBS in an explicit frame and units; immutable normalized parameter, retained through cuts/reversal. |
| Pose | Owner subsequently removed intrinsic roll; adapters derive it. Required tool-axis and independent material-section orientation are distinct. See the current [Paath proposal](0.4.0-paath.md). |
| Volume | Current research recommends local material per distance and aspect, with optional integrated totals. This supersedes the earlier cumulative-volume-first framing; existing profiles still need deliberate replacement. See the [Paath proposal](0.4.0-paath.md). |
| Velocity | Scalar physical speed in mm/s is sufficient with a tangent; a vector velocity would duplicate direction. It is a request, not realized machine acceleration/timing. Settle zero/negative speed behavior against existing intent. |
| Bead section | Volume and pose do not specify the deposited cross-section uniquely. Retain minimal section width/shape and material frame, or adopt an explicit deterministic section law shared by display, clearance and construction. Current width/materialNormal have real consumers; tool axis alone cannot replace the material normal. |
| Material/process | Material/tool-channel identity, prerequisites, atomicity, traversal permissions and process events belong to work/order records. Temperature/fan/dwell/tool change are explicit events/process context, not repeated per curve sample. |
| Provenance | IDs/source intervals and concise origin links live outside numerical channels. Layer membership and construction dependencies remain independent of reference surfaces and world Z. |
| Stationary work | Inject and timed in-place orientation have no moving arc length. Keep explicit event semantics/time domain; do not encode positive extrusion as zero-length moving Paath or invent microscopic travel. |

Travel uses the same moving primitive with zero material; Scheduler can add
neutral transfer intent. Export resolves selected-machine physical routes and
may produce additional travel. Show both with their stage and identity. Direct
Paath firmware would also need event, timing and machine-execution semantics; it
is not achieved by teaching firmware to evaluate a NURBS curve.

Trace can become a small authoring/finalization operation when a producer already
supplies admitted Paath and manufacturing metadata. Raw CAD curves still need
process, material, reference mapping and prerequisites. Consolidate those in one
shared operation and delete redundant conversion routes; preserve repetition and
reference authoring as helpers where they earn their place. Slice constructs
Paath; it does not become a parallel downstream representation.

Call the module **CAD toolkit** and its returned values **geometry** in the
viewer. Keep **Geometry** as the broader numerical owner for curves, frames,
queries and native lifetime. This improves labels without a disruptive file/API
rename or falsely moving shared numerical work into every producer.

## A finite set of inspection families

This is a proposed initial inventory, not a demonstrated upper bound on every
future extension. Record actual public wire types and omissions during migration.
A bounded registry with a faithful structured-data fallback lets most contracts
reuse a few viewers without pretending every type is a 3D shape.

| Family / peek point | Human inspection | Increment beyond today |
|---|---|---|
| Geometry, after import/CAD and each changed result | Native/mesh solids, components, curves, points, surfaces/trims, selected topology, frames, bounds and numerical/source details | Existing solid viewer reusable; standalone curves/points, trim/control-net inspection and non-solid charts need work. Derived meshes show tolerance/provenance and never become the native authority. |
| Regions/reference stacks, after allocation and before deposition | Claims, remainder/reservations, intersections, UV loops/holes, local normals, stack membership and prerequisites | 2D UV plus linked 3D surfaces and slice/stack isolation is substantial new inspection UI. Shared-material redesign stays 0.5.0; view current data without implementing it. |
| Paath, after construction/modulation/finalization and before scheduling | Curve geometry, source intervals, pose/frame glyphs, V/speed/section profiles, dependencies and raw values | Reader/rendering reusable; parameter-linked profile plots and unordered source inspection are new. |
| Ordered Paath, after Scheduler and Export preparation | Exact source coverage/order, cuts/reversal, prerequisites, transfer intent versus resolved travel, deposited prefix | Existing playback useful; order/constraint explanations and source-to-execution selection need work. |
| Recipe/settings/operation records, at request admission and Export capture | Captured values, units, defaults/provenance, revisions and differences | Structured inspector/diff; no new numerical engine. Must show resolved values as well as authored requests. |
| Findings/evidence, on a failed or refined operation | Offending operands/ranges, failed prerequisite, witnesses and bounds | Reuse geometry/path overlays plus a dependency graph. A conservative bound is labeled as a bound, never presented as an actual collision. |

Defer simulator-scale additions unless a concrete contract needs them: physical
filament/thermal prediction, arbitrary scalar/vector-field volume rendering,
whole-robot swept-volume/collision simulation and complete machine-program
playback. Current kinematics and nominal beads are not those guarantees.

## “Accurate and complete” needs data identity and inspection depth

A selected wire occurrence identifies flow/tool call, parent request/job,
contract/plug, type/version, producer, bundle/revision, artifact/value identity,
coordinate frame, sequence and stage. Concurrent calls and repeated uses of the
same plug must stay distinct. Carry this context across worker/process boundaries.
Link the value admitted by its downstream consumer, including any normalization;
if a plug transforms data, show its input and output as separate occurrences.

Retain immutable values or existing artifact references at declared boundaries.
For mutable working data, take the snapshot at ownership transfer or version it;
a late reread of the recipe/Bundle is not the historical value. Native handles
need a retained evaluator lease or a faithful immutable geometry record. Do not
serialize an evaluator as an empty JSON object. Inspection is read-only and
cannot mutate or unblock the running computation. Diagnostic snapshots remain
separate from Bundle's authoritative saved part state.

Record cheap references during normal work; fetch/tessellate/render lazily when
someone peeks. Use shared viewer adapters per type, selected capture and bounded
retention. Pin a value explicitly when it must survive cleanup; expired or
uncaptured intermediate data says unavailable rather than showing today's value
under the old identity. Retention, snapshot cost and non-serializable geometry
need measurements before claiming negligible overhead. Remote clients cannot
fetch a local-only URI; return authorized compact evidence or approved content
through the service when needed, with full values retained locally by default.

Pixels cannot expose every knot, prerequisite or hidden face. The inspector must
pair the graphic with complete typed data/metadata, selection/filtering and raw
access. Tessellation and LOD disclose error bounds, omitted content and active
filters; a partial picture cannot claim the complete-view contract. The same
numerical evaluator and authoritative values feed viewer and downstream consumer.
A rendered nominal bead is an accurate view of a declared section model, not a
claim of physical extrusion accuracy. Existing rectangular/oval bead routes and
fallback omission prevent claiming this inspector contract is already satisfied.
Unifying the section model is therefore a candidate 0.4.0 prerequisite if bead
inspection promises the same material geometry Scheduling consumes; its exact
scope needs agreement, rather than silently importing all deferred bead work.

## MCP and the relay

Retain the topology: remote MCP client → authenticated Worker/DO routing → outbound
device connection → local Application → the ordinary jobs, Bundle and Studio.
Local clients can use stdio or local Streamable HTTP backed by those same
operations. Define one service contract; CLI and MCP are adapters. Do not require
the cloud for local operation or move geometry/Bundle state to the relay.

The previous prototype is a useful implementation reference, not a drop-in
restoration. Current runtime/session selection, request reservations, workRequest
handback, Export capture and home ownership supersede its old local runtime.
Restoring an SDK dependency needs the existing dependency approval; no package
has been added in this assessment. Packaging's old MCP exclusion needs review.

| Structural concern | Proposed resolution |
|---|---|
| One current chat per device displaced older sessions | Bind each authenticated session to explicit runtime/Studio/request authority. Support current concurrent chats or deliberately settle a narrower service contract; don't revive implicit replacement. |
| Long calls, sleeps and deploys lose in-memory pending results | Local jobs outlive transport. Return accepted job identity quickly; status/cancel/result and event cursors reconnect to the same job. Do not retry mutations blindly or claim exactly-once execution from JSON-RPC IDs. |
| Reply lost after a successful mutation | Revision rejection alone cannot tell a caller whether its request succeeded. Reuse existing request identities/receipts where sufficient; add a bounded operation-outcome identity only where a real ambiguous retry remains. |
| Single shared DO serializes routing/storage and shares a failure domain | Keep it only while measured isolation/load are adequate; separate device routing by device identity if bottleneck or failure isolation warrants it. An object per session is not inherently required. |
| Long HTTP waits/timers undermine idle hibernation | Prefer short job/status calls and actual event delivery; outbound sockets can use hibernation. Do not inherit the old budget or assert idle hibernation while holding active waits. |
| MCP notifications do not make a host invoke the model | Separate protocol event delivery from the client-specific ability to resume an assistant. Demonstrate that behavior in each intended client; don't promise continuous chat from transport conformance. |
| OAuth/session confusion | Device secret, user grant, protocol session and local work authority are separate. Validate resource audience, grant, runtime and target on every call; preserve revocation and local Export confirmation. |
| Full inspection data over a cloud hop | Keep large geometry/path/program data local by default. Route compact typed results, scoped resource access and explicit inspection requests; measure latency/bytes. |

The published [MCP transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
defines Streamable HTTP, session handling and explicit cancellation; disconnect is
not cancellation. [Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)
defines resource metadata and token audience protections. [MCP tasks](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)
are experimental and negotiated; retain ordinary job/status operations for clients
without them. These are protocol references checked on 2026-10-20, not client
compatibility evidence. [Cloudflare hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)
keeps accepted sockets connected while resetting in-memory state; reconnect and
pending-call handling must account for that lifecycle. Re-measure cost/load
instead of reusing historical pricing or client deadlines.

## Developer guidance: retain intent, reduce incidental obligations

This review covered onboarding and its owners, AGENTS, BUILDERS, developer
context, contributing guidance, shared/local notes, core engineering guidance,
source toolkit, extension authoring, test policy, packaging and map history.
It is a document/history assessment, not a complete measured productivity study
or audit of every skill/machine manual.

| Guidance | Recommendation and reason |
|---|---|
| Roles, authorization, dependency/provenance rules, software versus physical evidence | Retain. These assign real authority and preserve evidence; contracts make permitted technical work clearer. |
| Bundle owns shared part state, private controller state, explicit ownership transfer | Retain as node/data contracts. Supplied immutable inputs make drift harder to express; copying everywhere is not required. |
| Every callee named; callable/state binding restrictions | Propose replacing blanket syntax rules with explicit state ownership and declared capability/effect rules. Local accumulators and selected callbacks need not be wrapped to satisfy a scanner. Registered plugins still need visible typed contracts. Historical triage shows costs, but does not prove every restriction caused a defect. Owner approval required before changing the current rules. |
| Command/query separation | **Keep**, explicitly reaffirmed by the owner, 2026-10-20: "I think we should keep command/query separation. It's good general practice." Queries answer without observable effects; commands act and return their allowed outcome. The earlier relaxation proposal is withdrawn. |
| Generic passthrough wires | Keep “needs a concrete reason”; a typed operation registry is justified at a service adapter. It must not smuggle private capabilities or conceal data transformations. |
| Tolerances and honest failure/partial-result semantics | Retain. Convert relevant guarantees into type/operation contracts. A literal-count baseline alone proves neither correct units nor correct numerical behavior. |
| Solve after every work cycle | Propose retiring mandatory solve from ordinary development once contracts ship. Retain analysis on changed boundaries/investigations. Local notes already contain a later full-solve deferral; reconcile both instructions explicitly. No solve was run for these prose edits. |
| Check cost, meaningful evidence and avoiding check spirals | Retain. Use schema/import checks plus representative contract flows. No coverage quota or new whole-suite gate. The local no-new-tests rule still applies; any policy change must be settled separately. |
| Repeated structure accounts and historical failure prose | Put each invariant in its contract owner; keep concise rationale and links. Map 0 + full developer context remains onboarding until the replacement is implemented and exercised. Propose shortening only after checking what useful decision criteria would be lost. |
| Duplicated hard-rule lists and local standing instructions | Establish one rule owner and discover it from both roles; keep local preferences local. Reconcile standing checkpoint permission versus generic “explicit authorization,” stale worker limits, focus behavior and cleanup without treating them as extra confirmation gates. |
| Stale guidance | BUILDERS still says developers orient by the map while toolkit/shared guidance says optional local maps. It also describes delivery through the same machine-program bytes while today's Studio reviews neutral Paath. Correct these against current behavior during guidance migration. |

The failures in developer context—proxy completion, preserving the old route,
losing semantics in replacements and claiming end-to-end evidence from local
checks—remain useful lessons. Contract maps help only if review checks actual
obligations and effects; a cleaner diagram alone would repeat the proxy failure.

## Proposed delivery increments and acceptance

1. **Settle root contracts and types.** Agree map semantics, Scheduler's plugs,
   Paath channels/interpolation and viewer completeness. Inventory public wire
   types and remaining decisions; record parent authority for agent submaps.
2. **Ship the contract reader/viewer.** Reuse selected design code/assets with
   provenance, stable IDs, layout, nested boundary navigation, links/types/source
   drilldown and separate conformance overlay. A fresh source checkout without
   the external map folder or analysis store can read map 0 and open the viewer.
   Developer onboarding and direct/MCP reads expose the same contract detail.
3. **Prove Scheduler/Paath inspection.** Capture one real generation flow before
   and after scheduling. Show identical source identity, exact coverage and
   preserved channels. Select a curve/range from the wire and inspect its values,
   profiles and order. Concurrent calls, cancellation and old snapshots retain
   correct identity; viewing does not rerun generation or affect its outcome.
4. **Reconcile engines by contract.** Map existing public interfaces and effects;
   fix unauthorized dependencies, duplicated conversion/section authorities and
   incomplete Trace finalization boundaries. Record violations explicitly until
   fixed. Evaluate geometry/region inspection through real native, mesh, trimmed,
   nonplanar, Inject and varying-pose examples; do not claim unsupported displays.
5. **Restore MCP over current Application.** Discovery/onboarding, edit, job,
   progress, cancellation, Studio handback and Export use the same handlers locally
   and through the relay. Exercise offline/sleep/reconnect/deploy, lost replies,
   concurrent sessions and revocation in intended clients. Protocol success alone
   does not establish a working human/agent workflow.
6. **Adopt settled guidance and close the release.** Replace old structure owners
   and conflicting instructions together. Human reviews contracts plus selected
   live values; source remains reachable. Record scopes of code review and runtime
   evidence, package checks and remaining gaps. No broad rewrite is complete just
   because its new labels appear on map 0.

The owner has set the release direction. The current deliverable is a useful human-facing contract-viewer prototype,
populated from discussed or established contracts. It may be incomplete. The
Paath numerical contract, inspection scope, remaining guidance changes and MCP
session/recovery details remain to settle, one decision at a time.
