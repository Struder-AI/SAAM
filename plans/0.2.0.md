# SAAM 0.2.0 implementation plan

Revised 2026-09-29 from the owner's supplied scratch specification and this task's
intent review. Supersedes the external draft, its separate slice/trace/inject
skills, ribbon sleeves and conflicting phase descriptions. [Overview](../TECHNICAL-OVERVIEW.md)
owns the conceptual inventory; [glossary](../GLOSSARY.md) owns terms. This is an
authorized build plan, not a claim of release readiness.

## Settled intent

- Author geometry. Defaults contain process/setup, not a starter shape. Explicit
  examples, gridfinity and heat-set feature construction remain useful.
- Compound geometry has components and optional boolean combination. Assembly
  has no combining operator, not no children. Preserve assembly identity and
  overlap semantics; do not build a mixed-face B-rep as a terminology change.
- Blob fields remain fields; extract meshes and retain the editable/sampleable source.
- A surface is geometry; cutting/reference is its role. To slice is to intersect
  for a toolpath reference, not generate a complete program.
- One general slice/deposition skill covers ordinary fill, brim, skin, wave,
  vase, lip, cladding, bridge and network in 0.2.0. Advanced tile patterns and
  line text use common curve operations. Convenient tool entries write common
  records. Actually replace duplicate producers; do not hide them in a dispatcher.
- Resolve ownership before sequence. The first-defined explicit claimant is the
  default principal, retaining the draft's deterministic choice. Establish
  compatible spacing and alternating overlap allocation, then derive scheduling
  constraints. Outside overlap preserve the intended cutting surfaces.
- Internal assignment boundaries intentionally receive walls. Top/bottom solidity
  follows actual part material, not ownership seams.
- Modulate before publishing final deposited geometry and constructing consumers.
  Bridges use finalized anchors, including upstream texture. Preserve sparse
  holes/openwork. Invalidate dependent results after upstream changes. Reject a
  specific unsupported coverage combination rather than using unmodulated support.
- Plastic rivets are hybrid: temporary process geometry plus injection. Supports
  remain distinct and need not own an authored volume.
- One bundle/revision/generation/review/delivery workflow; the person confirms
  settings and exact toolpath. This task authorizes no push, release or hardware run.

## Scope and deferrals

| Area | 0.2.0 | Deferred |
|---|---|---|
| Surface regions | Required cuts, region clipping and boundary operations | General joined trimmed-face solids: 0.2.1 |
| Sleeves | Periodic patches, structured mesh strips and valid contour-derived sleeves required by existing techniques | Arbitrary bent mesh recognition/parameterization and general family topology |
| Stacks | Horizontal/tilted planes, supported translated spline/roof references, local thickness and machine constraints | Constant-thickness normal-offset stacks |
| Ownership | Volumes/slabs, principal precedence, compatible slicing and alternating overlap; internal walls | Automatic design/load intent inference |
| Supports | Preserve selected-contact/footprint/tree behavior; reuse common operations where practical | Support redesign after 0.2.1 |
| Offsets | Native spline-section curves fitted to tolerance; polygon mesh sections; collision resolution, no ribbons | General NURBS solid boolean kernel/arbitrary mesh-surface geodesic offsets |
| Machines | Existing contracts and representable orientations/process actions | Full swept-head collision model and new physical acceptance |

The full sleeve definition remains broad; functions restricted to horizontal rings
must say so. Build no general sleeve/trimmed-solid framework merely to match a
definition when the release's constructions need less. Narrow exceptions to the
in-scope techniques need explicit rationale/evidence in progress, not silent deferral.

## Architecture and records

Named stages take/return data: evaluate geometry; construct cutting surfaces;
resolve ownership; evaluate owned surface regions; construct/offset/clip strokes;
connect/order; map to XYZ; calculate bead/process/axis; modulate/finalize;
publish deposited boundaries; compose; export/check. Coordinate mapping, bead
calculation and packaging deposition operations are separate responsibilities.

Builders settle exact records together before editing shared files. Keep the
existing versioned `plan.slices` location unless integration provides a concrete
reason to change it; the old draft's `composition.slices` is not another format.
Extend one assignment form for curved references, fronts, spirals and supplied
curves. Tool edits and bulk recipe patches write the same form. Geometry/process
variation is data; callbacks remain at real I/O/progress boundaries.

Implemented checkpoint: tilted/translated roof and spline families, common
constructions, assignment processes, modulation, finalized support, bundle tools
and Studio recipe displays are integrated. Direct software evidence is recorded
in DEVLOG and `.local/0.2.0`; this is not release or physical qualification.

### Ownership before sequence

1. Collect spatial claims independently of planned execution.
2. Resolve principal precedence for overlaps and diagnose incompatible constraints.
3. Establish compatible pitches, principal slice references inside shared zones
   and alternating material allocation before operation scheduling.
4. Construct each assignment's slices/strokes from those decisions.
5. Derive support/interlock/injection/boundary-consumption prerequisites. The
   composer may optimize only within those constraints.

Do not replace a tilted owner's entire family with its principal's horizontal
family: shared zones use principal references; the outside retains its authored
family with compatible spacing and connected transitions.

### Common construction coverage

| Use | Required construction |
|---|---|
| Ordinary/solid/hollow/fill-only | Loops, existing infill patterns, solid masks and adjustable spacing |
| Brim | Auxiliary first-contact outline band; outward loops, no modeled flange |
| Skin | Roof spline/height-field references, full crossing and local bead thickness |
| Wave | Allowed surface region, supported seed, offset fronts and continuous joining |
| Vase | Offset contours, correspondence, continuous spiral and level-end taper |
| Lip | Rim regions with changing loop count/shape through shared operations |
| Cladding | Periodic reference regions, directed/helical/crossed paths and declared tool/rotary mapping |
| Bridge | Spans, anchor portions, attachment motions and distinct process roles |
| Network/line text | Explicit centerlines, bead-width rule and independent grids |
| Advanced vase | Around/along/normal tile coordinates, repetition and continuous connection |

Retain physically exercised example behavior before removing old producers.
Compare geometry, volume, continuity and dependencies, not only final hashes.
Report intentional differences; software checks never confer print approval.

## Interface migration

Rename public operations and their live callers/manuals together:
`create_print` -> `create_bundle`, `list_prints` -> `list_bundles`, `get_print` ->
`get_bundle`, `adjust_print` -> `adjust_recipe`, `check_print` -> `check_bundle`,
`generate_print` -> `generate_toolpath`, `deliver_print` -> `deliver_toolpath`,
`get_plan_template` -> `get_recipe_defaults`, `import_thingi10k_print` ->
`import_thingi10k_bundle`. Delivery means checked machine-program/package bytes.
Use bundle identity consistently at public boundaries; avoid needless internal
file churn. Reconcile specialized local import naming without opening remote file
access. No compatibility aliases or parallel record formats before alpha.

Defaults supply setup/process/common assignment settings without geometry or
automatic specialized skin. Creation requires authored/imported geometry; tour
and demo shapes live with their explicitly requested examples. Remove
`heat_set_catalog` registration/prompt references; manuals list size/profile choices
backed by implementation dimensions (thread size alone can be ambiguous).

`slice` edits general deposition; `modulate` edits its fields. Curve deposition
and rivets remain accessible through common recipe data. Do not recreate separate
mandatory trace/inject skills or tools. Add conveniences only for concrete needs.

## Verification, limits and completion

Direct checks cover the named constructions, export/interpretation, edit/bulk
parity and final support. No new tests or whole suites; existing fixtures are
mechanically migrated. Full workflow regression and physical qualification remain.
Preserved machine limits constrain translated references and local bead gaps.

Walk affected maps before core/Studio edits. The lead coordinates regeneration
after integration, without running the solver, and rereads changed boundaries.
Modified sleeve foundations/rim contact, bridge attachment displacement and posed
modulation reject explicitly. Cladding retains its authored chart and rejects
samples outside final substrate beads. Ordinary unmodulated skin retains its
nominal supporting-layer model; explicit or modulated support uses actual beads.
Checkpoint locally under CONTRIBUTING-AGENTS.md; no push/release/hardware.

0.2.0 is complete only when in-scope techniques use shared operations, current
schemas/tools/manuals agree, representative executions establish the claims, and
deferrals remain explicit. A completed worker milestone is not a completed release.
