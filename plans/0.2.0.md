# SAAM 0.2.0 implementation plan

First alpha; revised 2026-09-29. This plan owns acceptance, the [overview](../TECHNICAL-OVERVIEW.md)
architecture, and the [glossary](../GLOSSARY.md) terms. 0.2.x is for patches; [0.3.0](0.3.0.md) owns upgrade intents.

## Settled intent

- Author geometry or standalone Trace/Inject. Defaults contain process/setup, not a starter shape. Explicit
  examples, gridfinity and heat-set feature construction remain useful.
- Compound geometry has components and optional boolean combination. Assembly
  has no combining operator, not no children. Preserve assembly identity and
  overlap semantics; do not build a mixed-face B-rep as a terminology change.
- Blob fields remain fields; extract meshes and retain the editable/sampleable source.
- A surface is geometry; cutting/reference is its role. To slice is to intersect
  for a toolpath reference, not generate a complete program. Target layer height
  means area-weighted mean normal projection of translation over the entire
  reference; local gaps vary and set bead volume. Default direction likewise
  uses the entire reference, independent of material intersection. Measure actual
  deposited contact at interfaces; nominal spacing is not an exact normal-ray fit.
- Use three construction families: Inject at points, Trace along spatial curves,
  and Slice over 3D regions through slices and slice families. Inputs may be
  authored or skill-generated. Normal vase, lip, skin, wave, brim and cladding lower to
  Slice; explicit centerlines, tiles, networks, line text and bridge spans lower
  to Trace. Rivets are hybrid: Slice reserves the shafts/basins and constructs
  enclosing material; Inject deposits at the planned points. Hybrid planners feed
  these same families. Advanced vase repeats and maps explicit Trace paths through
  a sleeve; those paths are the tile, with no alternate tile representation.
  Guidance composes these operations without separate technique recipe formats.
  Ordinary Slice retains loops, infill patterns, solid masks and adjustable spacing.
- Substrate adaptation is agent-controlled, without a Studio toggle; default is `experimental:{substrateAdaptation:false}`. Missing
  substrate-adaptation fields migrate explicitly; loading a recipe never
  rewrites it. `experimental.substrateAdaptation` is opt-in. OFF uses nominal
  references and skips final-material contact/remapping. ON uses finalized
  deposition for gap/volume adjustment or surface-following placement, while
  keeping required-contact and gap rejection. Explicit dependencies and bridge
  anchor checks apply in both modes. Acceptance compares correctness, measures and
  reports runtime, volume and XYZ; there is no ON runtime threshold. General gap
  filling is rejected, not deferred; compensation changes existing deposition.
- The first-layer footprint is the part/build-plate intersection. A raised sleeve
  course is a separate construction. Standalone Trace/Inject needs no placeholder
  geometry.
- Material-overlap/shared-ownership integration is deferred to [0.3.0](0.3.0.md),
  explicitly requested 2026-09-30. Competing material overlaps return unsupported;
  shared boundaries within geometry tolerance are allowed. Do not claim general joints.
- Schedule dependency-ready operations by actual maximum Z. Optional layer batching moves to [0.3.0](0.3.0.md).
- Internal assignment boundaries intentionally receive walls. Top/bottom solidity
  follows actual part material, not ownership seams.
- Modulation applies optional effects to an otherwise valid toolpath, primarily
  visual and surface effects. Other useful applications remain open, not required.
  Effects finalize before consumers query relevant deposited path fragments;
  preserve holes and actual bead dimensions, without a distorted solid/mesh.
  Gap-volume compensation, contact adaptation, nozzle orientation, ownership and
  sequencing work independently of modifiers. Brick layering belongs to slice
  construction; graded infill density was not requested and is outside this plan.
- Supports are separate sacrificial assignments requiring no authored volume.
  Preserve selected-contact, footprint and tree behavior; redesign is deferred.
  There is no overhang-percentage model or new physical qualification.
- Geometry supplies bead frames; Slice optionally derives upright or normal-aligned poses, with optional FIELD tilt, without
  machine compatibility gates. Exporters own machine adaptation/checks. Surface
  displacement effects define smooth transitions intrinsically; scalar effects
  may step. Exact acceleration modelling does not block this release.
- One bundle/revision/generation/review/delivery workflow; the person confirms
  settings and exact toolpath. This task authorizes no push, release or hardware run.

## Scope and deferrals

| Area | 0.2.0 | Deferred |
|---|---|---|
| Surface regions | Required cuts, region clipping and boundary operations | Joined trimmed-face solids: [0.3.0 intents](0.3.0.md) |
| Sleeves | Periodic patches, structured mesh strips and valid contour-derived sleeves required by existing techniques | Arbitrary bent mesh recognition/parameterization and general family topology |
| Stacks | Horizontal/tilted planes, supported translated spline/roof references and local thickness; machine checks belong to export | Constant-thickness normal-offset stacks |
| Offsets | Native spline-section curves fitted to tolerance; polygon mesh sections; collision resolution; rounded joins for normal offsets at sharp creases, no ribbons | General NURBS solid boolean kernel/arbitrary mesh-surface geodesic offsets |

Supported subsets must state their limits; in-scope exceptions need evidence, not silent deferral. [0.3.0](0.3.0.md) collects future intents.

## Architecture and records

Named stages take/return data: evaluate geometry; construct cutting surfaces;
resolve ownership; evaluate owned surface regions; construct/offset/clip strokes;
connect/order; map to XYZ; calculate bead/process; adapt machine pose; modulate/finalize;
publish deposited boundaries; compose; export/check. Coordinate mapping, bead
calculation and packaging deposition operations are separate responsibilities.
Travel optimization should generalize across Slice use cases. Inject and Trace
retain dependencies and authored continuity without requiring elaborate optimization.

Builders agree records before shared edits. Keep versioned `plan.slices` unless
integration requires a change; `composition.slices` is not another format. Tools
and bulk patches share assignment records for references, fronts, spirals and curves.
Geometry/process variation is data; callbacks stay at real I/O/progress boundaries.
The Ousterhout-video refactor is a release goal: deep operations, small interfaces,
hidden implementation knowledge and fewer invalid states. Review designs; avoid
shallow wrappers, speculative frameworks and splitting merely by function length.

Owner decisions supersede the draft; unrevoked requirements remain binding and implementation limits are not deferrals.

Shared-region overlap integration and its acceptance now belong to 0.3.0.
This deferral does not remove existing region selection, ordinary spacing,
substrate compensation or dependency/contact checks.

Retain exercised behavior; compare geometry, volume, continuity and dependencies, report intentional differences, and never infer print approval from software checks.

## Interface migration

Rename public operations and their live callers/manuals together:
`create_print` -> `create_bundle`, `list_prints` -> `list_bundles`, `get_print` ->
`get_bundle`, `adjust_print` -> `adjust_recipe`, `check_print` -> `check_bundle`,
`generate_print` -> `generate_toolpath`, `deliver_print` -> `deliver_toolpath`,
`get_plan_template` -> `get_recipe_defaults`, `import_thingi10k_print` ->
`import_thingi10k_bundle`. Delivery means checked machine-program/package bytes.
Use bundle identity consistently at public boundaries; avoid needless internal
file churn. Reconcile specialized local import naming without opening remote file
access. No compatibility aliases or parallel record formats before alpha.

Defaults supply setup/process/common assignment settings without geometry or
automatic specialized skin. Creation requires geometry or standalone Trace/Inject; tour
and demo shapes live with their explicitly requested examples. Remove
`heat_set_catalog` registration/prompt references; manuals list size/profile choices
backed by implementation dimensions (thread size alone can be ambiguous).

`slice` edits shared deposition records; `modulate` edits their fields. Trace and
inject retain distinct contracts. Standalone point injection uses the shared
recipe/edit API and rivet injection machinery; a separate tool is optional.
Reconcile modulation schemas/manuals with the visual/surface focus. Speed/tool-axis
profiles and injection scaling are not modulation requirements. Retain useful
field evaluation without requiring a general technical modifier system.

## Verification, limits and completion

Direct checks cover the named constructions, export/interpretation, edit/bulk
parity and final support. No new tests or whole suites; existing fixtures are
mechanically migrated. Final software integration remains; physical qualification is ongoing across releases, not assigned to 0.3.0.
Input/representation limits stay explicit; machine compatibility belongs to export.

Walk affected maps before core/Studio edits. The lead coordinates regeneration
after all implementation/integration, per owner, without the solver; reread changed boundaries.
Resolve valid-input failures or present their concrete limitations and alternatives to the owner.
Checkpoint locally under CONTRIBUTING-AGENTS.md; no push/release/hardware.

0.2.0 is complete only when in-scope techniques use shared operations, current
schemas/tools/manuals agree, representative executions establish the claims, and
deferrals remain explicit. A completed worker milestone is not a completed release.
