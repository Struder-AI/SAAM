# Session intent audit

2026-10-20. Parent agent's own review of the owner's instructions in this
conversation, current contracts, implementation ledger and changes since
`b0d6dd27`. The separate [baseline audit](0.4.0-baseline-audit.md) examines
pre-migration behavior; that task is delegated, this review is not.

## Confirmed process omissions

1. **Workers must use the maps as their authority.** The owner described this
   at the beginning: onboarding returns map 0, agents select further maps, and
   code disagreement calls for correction rather than disregard. Initial worker
   assignments used file ownership and prose summaries without requiring actual
   contract reads or authoring before implementation. Later adding those reads
   does not make the earlier work contract-led. Correction: actual reads and
   owning plugs are recorded in each active workstream; mismatches are reviewed
   before new implementation. Root responsibilities, boundaries, plugs and
   external promises need owner approval to change; internal refinements must
   satisfy their enclosing contract.

2. **The human reviews intended architecture through the map.** Contract/type
   authoring lagged implementation: /3 writers were being changed while the
   Paath card still described degree/interpolation as an open investigation.
   Prose plans and the map retained pause/proposal wording after work resumed.
   This makes the human's view an unreliable review surface and pressures agents
   to follow messages instead. Correction: author detailed type/submap contracts
   before dependent work, keep implementation status separate, and reconcile
   stale instruction text without treating it as permission to ignore contracts.

3. **Explicit operation visibility.** A 61-name migration inventory was used
   where drill-down to operation contracts was needed. It did not expose every
   parameter, effect, outcome or owner. The owner's subsequent all-commands and
   submaps-only index requirements make the missing behavior unambiguous.
   Correction now exposes 67 call operations and 14 accepted top-level CLI verbs
   through one authored catalog, complete schemas/effects/outcomes and shared
   agent reads. The comparator finds no registration/schema/binding or CLI-policy
   mismatches, but records 56 unresolved obligations across 55 operations. Those
   include unverified ownership, not 56 independently proven runtime defects.
   Command visibility is not proof that implementation obeys its contracts.

## Scope retained or intentionally changed

- Previous 0.4.0 intent was moved to 0.5.0, with its status and scope. Do not
  quietly pull full carriage/fixture collision avoidance or shared-material
  redesign back into this release. Current nozzle-cone qualification must state
  its limits; it is not full-machine collision certification.
- The approved SAAM responsibility wording remains exact. Context and Extensions
  remain distinct, Scheduler remains at map 0, and the map does not map itself.
- Source/map Alt-click, graph node/wire contract clicks, boundary plug direction,
  direct dragging, aggregation and balanced nesting remain requirements. The
  JavaScript renderer was compared structurally; background visual verification
  is still incomplete and cannot be inferred from box dimensions alone.
- Machine-independent Paath, no intrinsic roll, logical tool indexes, optional
  estimates and splitting into separately indexed entities are deliberate owner
  changes, not regressions to reverse under compatibility pressure.
- The installed application plus local extensions is now the default builder
  route. A core checkout is explicit developer work. Desktop/web share local
  overrides. The new install guide is a draft for owner review, not a release.

The migration is active, not complete. Outstanding items above must remain in
the implementation ledger and owning contracts; a passing map-schema check is
not implementation conformance or an end-to-end migration result.

The completed baseline review found three concrete regressions/risks requiring
correction: finalized section/material drift, rejected previously valid zero-flow
authoring, and a discontinuous computation frame consumed as robot roll. It also
identified saved-output Export and client event acknowledgment compatibility
risks. These are detailed with evidence limits in the separate baseline audit;
they are not approved consequences of the Paath redesign.
