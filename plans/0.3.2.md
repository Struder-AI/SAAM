## First new bug: prefer the installed release for maker work

**Observed:** repository and installed 0.3.1 `AGENTS.md` route directly to relative checkout commands; onboarding reports Git/main currency, not installed-release selection. A stale checkout can therefore launch a different Studio/runtime without the installed release's update-service wiring. Separately, the shared checkout was 24 commits behind the release branch. Updating that checkout alone does not fix the general launch rule.

- Before ordinary making, tours or a new Studio launch, discover the installed release and any applicable running instance. Report its version/runtime/data location and use its bundled runtime, tools and service-aware launcher; reconnect to the intended instance without stealing another agent's bundle association.
- Keep deliberate source development explicit. An arbitrary current directory or a Git sync report must not silently select a checkout over the installed app. If no release is installed, follow the [installation guide](../packaging/INSTALL.md); preserve user data and local extensions. Optional activation and service outages must not block local use; use the existing in-app update flow for offered updates.
- Fix the actual entry guidance and launch/context paths together: [agent entry](../AGENTS.md), [maker guidance](../MAKERS.md), [toolkit](../core/agent/README.md), [Studio](../studio/README.md), and [packaging](../packaging/README.md). Acceptance: on supported desktop clients/platforms, an installed newer release plus an older checkout starts/uses the installed release for maker work; explicit development still uses its selected checkout. Verify missing installation, already-running ownership, unavailable service and update/restart with data preserved. This intent records the fix; implementation is pending.
