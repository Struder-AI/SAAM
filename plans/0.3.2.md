## Small, truthful map reads and complexity reduction

**CLI map reads — owner revised 2026-10-02:** one default supplies parent-map interactions and exact source ranges; agents read leaf code with normal file tools, never another map read. Remove `--source`, `--code` and `--details`; direct contract/link reads supply complete interfaces. Preserve the human viewer. The [map read contract](../dev-map/README.md#commands) owns mechanics and replacement requirements: integrations must carry the existing semantics rather than bypassing the presentation boundary. Keep orientation short and visible information complete; no truncation, hidden summaries or return to historical oversized reads.

**Complexity rule, owner direction:** a special-case branch, alternate producer, compatibility shim or repair pass is evidence that the operation/interface may be wrong. Before adding one, identify the common operation and the invariant that could make the exception unnecessary. For Slice, the accepted direction is one owned-region/reference-family operation; lip, cladding, skin, brim and support become inputs, not separate lifecycles. When a general operation replaces an old path, rewire every consumer and remove the old path, dispatch and stale guidance. Review the actual before/after call paths and owner boundaries, identify every surviving special-case path, and justify any irreducible physical exception with a concrete constraint. Closing a worker milestone requires the lead to verify the original user-visible outcome on its real entry path and the removal of superseded paths; parity, static map checks and narrower lifecycle tests establish only their stated properties. Passing tests, short functions or a map with fewer boxes do not by themselves establish reduced complexity. This is an implementation/review criterion across 0.3.2, not a proposal to add another wrapper or slogan.

## SAAM application, chats and folders

**Owner direction, 2026-10-02:** one SAAM application per installation owns Studio instances, chats, jobs, prints and the release service. Studio first and chat first differ only in how the first chat attaches. Everything after attachment is shared. Alpha testers and contributors use the relay-connected release. **Current gap:** [launcher](../packaging/launch.mjs), [MCP](../adapters/mcp/src/server.mjs) and [toolkit preview/tour](../core/agent/toolkit.mjs) each create their own runtime or Studio, owner identity, Prints root, lifetime rule and diagnostics state. A chat therefore cannot reach an already open Studio, and tours reach no relay. 0.3.1 also left `.studio-requests` inside its replaceable program folder.

- **Tray application:** the app starts from its icon or on a chat's first command and shows a Windows notification-area or macOS menu-bar icon with Open Studio, Update and Quit. It runs until Quit or an update. Closing tabs or chats never stops it. Quit warns about running jobs. Use OS-provided scripting for the icon (PowerShell on Windows, `osascript` on macOS), with no new dependency. This replaces the three-second tab, thirty-minute viewer and chat-disconnect shutdowns.
- **No MCP:** scope is Codex Desktop and Claude Code Desktop, which both run commands. One installed `saam` command calls the app's local control interface: a general operation call, operation help, and a wait for Studio requests and events, all answered by the running app. In 647 Codex sessions (2026-09-02 to 10-02) and the local Claude Code transcripts, there were no SAAM MCP calls and Codex has no `saam` entry; Codex used the checkout toolkit. Remove the MCP adapter, the stale Claude plugin and the toolkit preview/tour/reattachment (`--studio`, `--agent-owner`) routes. The tour starts through `saam`. Pass input by stdin, file or flags, because PowerShell 5.1 mangles quoted JSON arguments.
- **One SAAM home, no new folders:** `C:\SAAM` on Windows, `~/SAAM` on macOS, containing `app/` (replaced by updates), `Prints/`, `extensions/` and `state/` (logs, relay credential, running-instance record, update download). There are no per-chat or registered workspace folders and no other Prints roots. The 0.3.2 installer, including the in-app update from 0.3.1, moves `%LOCALAPPDATA%\SAAM` and `%LOCALAPPDATA%\Programs\SAAM` (and the macOS equivalents) into this layout, preserving all user data. Verify write access for a second Windows user.
- **Chat identity:** `saam` sends the client's chat session ID from the command environment. `CLAUDE_CODE_SESSION_ID` is verified. Codex is unverified: the `CODEX_SESSION_ID` string appears in the codex 0.159.2 binary, so check a Codex chat's environment. If it is absent, `saam` returns an ID on the first command and the agent passes it back. The threat model is one user's own chats: prevent accidental wrong attachment, not authentication between chats. No one-use handoff, replay protection or hooks.
- **Attachment:** each Studio window has zero or one attached chat, and a chat may own several windows; Studio names the attached chat. *Studio first:* a Codex or Claude Code button opens that client in the SAAM home and the window shows Waiting for agent. The first command from a chat unknown to SAAM attaches to that waiting window, and Studio allows re-pairing. *Chat first:* an unknown chat with no waiting window gets a new window on its first review. *Resume:* the same session ID reconnects to its windows. A detached window stays open and can be claimed by naming its print. One Studio per bundle, Bundle reservations/revisions, requests, cancellation and checked-byte export are unchanged.
- **Client setup:** fresh installs and the update from 0.3.1 put `saam` on PATH, register a user-level SAAM skill for chat-first discovery and allowlist `saam` commands in each detected client. Unrelated settings are preserved. Studio offers retry for absent or old clients, and registration failure never breaks SAAM. The SAAM home holds the guidance a Studio-first chat reads at startup. [Codex deep links](https://learn.chatgpt.com/docs/reference/commands#chats) open a workspace with an unsent prompt. [Claude --desktop](https://code.claude.com/docs/en/cli-reference) opens the current directory with no prompt (v2.1.285+). Report any required first Send honestly. In Claude Code, a background `saam wait` re-invokes the agent when a Studio request arrives; Codex's equivalent is unverified.
- **Diagnostics:** the release service attaches once, in the app, for both directions, tours, operations and workspace jobs, using the existing redaction and consent. Acceptance requires an acknowledged relay receipt from the actual instance, including local-extension execution.
- **Checkouts, source runs and extensions:** a checkout lives wherever its git repo is and is needed only for core/shared changes or shipped guidance. A source run uses the same SAAM home and relay credential, one app at a time, reporting `development (<commit>, dirty)`. Accepted risk: it may save bundle formats an older release cannot read. Local extensions in `extensions/` already run in the installed release: on 2026-10-02 all 20 entries of the 10 bundled extensions with entries loaded from a copied data folder, because entries receive engine operations rather than importing app files. Compatibility is limited to operations the running release supplies; changed scripts need a restart. Workspaces follow once the workspace extension class below ships.

**Acceptance:** both directions in both clients, two simultaneous chats, resume, Quit from the tray, the 0.3.1 → 0.3.2 update with data migration, a source run beside the release, a local extension, and relay receipt from each. Update [agent entry](../AGENTS.md), [maker guidance](../MAKERS.md), [toolkit](../core/agent/README.md), [Studio](../studio/README.md), [developer context](../DEVELOPER-CONTEXT.md), [install guide](../packaging/INSTALL.md) and [packaging](../packaging/README.md) together; retire [adapter](../adapters/mcp/README.md) guidance with its code. Use practical trials and focused existing checks, with no new tests or whole-suite run.
