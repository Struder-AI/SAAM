This incorporates the original map discussions and subsequent corrections; current code, historical logs and audit assignments do not override intent. Material overlap and other deferred features remain in [0.4.0](0.4.0.md); physical qualification continues across releases.

- **Impose the map to simplify the implementation.** For each crossing or unknown, first assess whether direct wiring, explicit operations or a responsibility change removes unnecessary indirection; implement the simpler design while preserving useful behavior. Improve the scanner for ambiguity that remains in justified code. Neither scanner work nor compliant-looking wrappers substitute for architectural rewrites. Root boundaries first, submaps next, leaf optimization last; remove superseded paths.
- Every wire is an inspectable/printable contract: operations, values, effects, errors and exclusions. Arrows express causal information/actions; permitted call/read directions are explicit and may run oppositely. No hidden/transitive access or pass-through channels to legalize old coupling.
- Assign every declaration to one map-0 owner, even within mixed-owner files. **Existing leaf assignments and authored nesting are provisional, not authoritative.** Derive leaves from component interactions: enclose declarations whose causal effects remain within the boundary, preserving external calls, resource/state effects and unknowns there. Recompute leaves and collapse unnecessary nesting; do not preserve old subdivisions or chase lower counts. Automate evidenced containment; unresolved targets do not prove it. Component-private utilities may fold; shared domain policy needs its actual owner/interface.
- Bundle is the only non-exclusive/shared **part-state** object. Sequential stages may mutate exclusively owned inputs and hand results forward, with no retained mutable aliases or lookbacks to a shared changing source. This does not require copying every stage. Studio, engines, jobs and installation services may own private state; Bundle commits supplied proposals.
- Significant new map-0 changes require owner discussion. The original `20260930_211155.jpg` establishes causal flow; its question marks were unresolved design. The [architecture set](../dev-map/sets/030-architecture/architecture.json) retains its existing identifier after this release split; contracts/submaps remain provisional. [Map authoring](../dev-map/README.md#authoring) owns mechanics; no solver moves authored boundaries.

Output/setup-only changes must not reconstruct unchanged neutral deposition. Existing `completeMachinePath` is not an API to preserve by passing machine facts through other components. Neutral-input currency and checked-output currency must reflect their different dependencies; avoid speculative compatibility/migration machinery.

## Retained behavior and extensions

- Preserve useful geometry/techniques, machine/exporter scope and ordinary Studio viewing. Text, heat-set inserts and Thingi10K become extensions without losing their operations. Record retained/removed/deferred capabilities and verify real workflows; desktop-only deployment/removal of web-chat machinery is owned by 0.3.0.
- Add portable hole-support and single-line-text plugins (owner, 2026-10-01); hole support targets bed-facing circular counterbores in whole-component planar printing. Single-line text ships one bead per centerline; parallel beads require a local builder edit, not a shipped option. General support redesign stays in 0.4.0.
- Saved geometry and SAAMpath remain viewable without extension code; regeneration reports missing prerequisites. Use the recipe's actual extension references, not a second mandatory dependency/version registry.
- **One Studio instance per bundle.** An agent may own several instances; separate agents own separate instances. Associate/release through Bundle, preserving stale/cancelled-job protection. No separate viewer/editor ownership modes or special multiple-viewer Export workflow.
- Export saves the checked program displayed, confirming its settings and exact toolpath together. No regeneration, repeated checking or added ceremony. Hide Export immediately when an update queues, using existing pending-update state and relevant revision/currency checks.
- Keep interactive teaching. The owner authorized a worker-designed [five-lesson tour](0.3.1-tour-policy.md), followed by a personal tryout. Use [struder.com/saam](https://struder.com/saam/) as the format reference; its separate webmaster owns the [website alignment](0.3.1-webmaster-request.md). [Discussion items](0.3.1-discussion.md) distinguish approvals from proposals. Remove unused direct Studio extension-request hooks; interactive additions use Specialized workspaces.

Extensions live separately from bundles; builder work may override release extensions. Preserve local edits outside replaceable defaults and use one deterministic selection for manuals, edits and actual regeneration. Portable scripts compose public engines, not mirrored installations, loader hooks or private API bags. Exchange manifest/guidance/scripts/assets/provenance/license without executing on import; promotion is explicit and individually reviewed, never automatic collection. No speculative compatibility framework, support windows or migration system; give specific guidance only for actual breaking changes.
Extensions are ordinary local code, without promised sandboxing/enforced IO permissions. Conformance applies to analyzed SAAM/adopted extensions, not arbitrary scripts. Resource extensions declare search/retrieval, return assets with identity and available provenance/license, and prefer saved assets over repeat downloads. Internet transport grants no implicit component permission; callers persist imported assets in Bundle. Geometry supplies reusable operations; extension-specific composition stays in Extensions.

Accepted wing scope: `npm run workspace:wing`, full-plane display but wing-only printing, integrated upturned winglets, straight rod passages, upright continuous Trace curves and outer sections on the flat winglet face; no flight qualification. Only TK-DEV `217a6e0`'s standalone renderer was adopted. Save all bundles creates a new set under `Prints/wing-workspace` (or `SAAM_DATA`) with `design.json`, `export.json` and a self-contained bundle per piece carrying geometry, explicit Trace, source parameters and protected construction requirements. Thermal settings/placement remain editable; one copied agent request addresses the set. SAAM owns generation/export/checking/confirmation. Regeneration preserves prior Studio edits by creating a new set; breaking requirements needs explicit source detachment. No live synchronization, shared coordinator or wholesale prototype adoption.
