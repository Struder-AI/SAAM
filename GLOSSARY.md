# SAAM glossary

Terminology: [architecture](ARCHITECTURE.md), [cumulative intent](intent/README.md).
Paath, SAAMpath and path are equivalent domain terms (owner, 2026-10-20).
The [shared Paath /3 contract](core/path/README.md) defines their numerical
meaning; [0.4.0](plans/0.4.0.md) owns the migration and remaining implementation.

| Term | Meaning |
|---|---|
| Bundle | Saved geometry, operation recipes, neutral SAAMpath, review snapshots and export receipts for a fabrication task. It stores and serves supplied work; a bundle can contain many recipes. |
| Recipe | An authored plan for one operation, including the inputs and settings that operation needs. |
| Paath (SAAMpath; path) | The machine-independent format for paths and stationary actions, carrying geometry and the full set of manufacturing attributes. Conditioning stages set or change attributes in this same format; other attributes can remain at defaults defined for that stage or unset. |
| Paath conditioning | Establishing or changing properties of Paath, such as material delivery, section aspect, tool direction or execution assignment, while retaining the same representation. Which properties are required depends on the operation consuming it. |
| Toolpath skill | Constructs deposition/process operations through shared core capabilities; named techniques may be configurations of the same skill. |
| Core skill | A developer-owned agent interface to core capabilities; geometry, toolpath and hybrid describe its function. |
| Guidance skill | Instructions and examples composing existing capabilities; builders author it without adding a deposition family or alternate recipe format. |
| Geometry skill | A skill that makes, fetches or changes the part's geometry before any toolpath exists. Each change is a new geometry revision. |
| Hybrid skill | Constructs part or temporary process geometry together with deposition, such as insert reinforcement or plastic rivets. |
| Keyword skill | A skill whose digest description is only its keyword, such as `gridfinity`. The agent uses it only when the person names that keyword, and reads its manual only then. |
| Slice | A construction operation that applies a recipe to one supplied body's material on one supplied slice surface, producing wall and infill Paath and reusable interior material. Its supplied stack member identifies the surface, its relationships and the regions requesting full fill. |
| Core construction families | Inject constructs deposition at points; Trace along supplied curves; Slice constructs wall and infill Paath on supplied slice surfaces. Inputs may be directly authored or generated by a skill; these families do not dictate the number of manuals, skills or tools. |
| Slice surface | A planar or curved reference surface on which Slice constructs deposition paths within the assigned material’s intersection with that surface. |
| Slice stack | The recipe-defined sequence of identified slice surfaces, with their domains, physical spacing and predecessor relationships. Each member has requested full-fill regions. Stack order describes geometric relationships; it is not the manufacturing schedule. |
| Full-fill regions | Regions where the recipe requests solid fill on a particular slice, including skin and explicitly requested solid areas. Slice applies them to its fillable interior after wall reservation; they describe requested fill, not deposited coverage. |
| Surface region | A bounded portion of a surface, possibly with holes or disconnected components. |
| Material ownership | Spatial responsibility resolved before execution order: explicit claims and a default remainder. |
| Dependency | A must-come-first relation that a skill, agent or native slice stack declares, naming the completed work it depends on: a stack member's predecessor, another operation, a layer or a course. Declaring it is a guarantee: within the declaring scope, the dependent work has no foundation or nozzle-clearance problem with its declared ancestors, and nothing downstream checks that again ("When you declare a dependency, you guarantee the thing you are making is not going to collide with that dependency", owner, 2026-10-20; "Dependencies are considered foundation safe", owner, 2026-10-22). Everything else is the Scheduler's to resolve: different branches, separate trees, undeclared work, and material entering a stack member over another producer's work. A dependency fixes readiness, not adjacency: the dependent work need not print immediately after. Ordering-only constraints (composition order, required enclosing material) rule nothing out. Agents are responsible for declaring dependencies; a missing declaration means the Scheduler checks that interaction. |
| Manufacturing prerequisite | A completion condition that must be satisfied before dependent fabrication work may begin; a declared dependency is one. |
| Completion | A condition representing finished work, including a native member that produces no deposition. |
| Supports | Auxiliary printed structures that carry or stabilize selected areas of a part during fabrication and are intended for removal afterward. Their placement and form are chosen using judgment about printing and removal. |
| Substrate | The surface or previously deposited material beneath a deposition location, including the build plate. It need not be a sacrificial support structure. |
| Compound geometry | Component solids with an optional boolean operation. Assembly preserves components; boolean modes combine their material. |
| Sleeve | A surface closed around one direction and open along the other, or a mesh with equivalent tube-side topology. Smooth periodicity is stronger than coincident seam edges. |
| Tile | An authored explicit path or set of paths used as a repeating unit; no separate tile representation. |
| Course | A deposition path regarded as one line, open or closed, straight or curved. What counts as one course is somewhat subjective and depends on the construction being described; courses may connect, and their boundaries need not coincide with extrusion starting or stopping. |
| Turn | One full revolution around a sleeve, which may rise continuously along a spiral without closing or stopping. |
| Pattern | An arrangement of paths, such as an infill pattern or repeated sleeve tiles. |
| Modulation | An optional effect on an otherwise valid toolpath, primarily for visual appearance and surface texture, with other useful applications left open. Required construction and process compensation work independently of modulation. |
